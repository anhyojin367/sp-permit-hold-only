## 2. MD 작업을 이어받는 방법

- `sp_pdf_judger/rules/document.md`: 문서 공통 실행 규칙.
- `sp_pdf_judger/rules/sky_covione.md`: 제품별 기간·필수 시험·제조정보·단위·수치·정성 표기 등 실행 규칙.
- `sp_pdf_judger/domain_details/`: LLM에게 제공하는 해석 문맥. 자유 서술을 추가했다고 독립 검사 항목으로 자동 실행되지 않는다.
- `docs/examples/`: 작성/검토 예제. 운영 규칙과 구별한다.
- `rules/_...`의 검토 설정은 각 문서의 활성화 조건과 근거 계약을 확인한다. 모든 초안이 활성 규칙은 아니다.

규칙은 `id`, `operation`, `selector`, `params`, `instruction` 등 지원 스키마에 맞춰 작성한다.
제품/제조단계/시험 범위를 좁히고 정상·오류·경계·근거 누락 사례를 함께 추가한다.
기존 연산의 수치·조건 변경과 의미 해석 지시는 MD로 바꿀 수 있지만, 새 필드 추출이나 미지원 연산은 Python 구현도 필요하다.

```powershell
python scripts/validate_rules.py
python -m pytest tests/test_policy_configuration.py tests/test_feedback_20260929.py -q
python scripts/validate_corpus.py --output-dir .local_validation/new_rule_offline
```

[MD_RULES_GUIDE](MD_RULES_GUIDE.md)의 스키마·작성 예제가 실제 기준이다. D번호/파일명으로 판정을 강제하는 규칙은 만들지 않는다.

## 3. 데이터와 재현 방법

`더미데이터/`의 D00~D16, 더미 허가서, 판정기준 Word는 사용자가 공개를 승인한 합성 자료다.
`scripts/validate_corpus.py`의 기대값은 검증기의 정답이며 운영 판정기에 주입되지 않는다.
D15 `x`, D16 `불검출`은 정상 표기 변형으로, 잡아야 한다는 것은 잘못 불충족 처리하지 않는다는 의미다.

`tests/fixtures/historical/`에는 과거 추출/판정 JSON 40개를 고정 입력으로 포함한다.
`python scripts/prepare_test_fixtures.py`는 이를 현재 위치에 맞춰 `.local_validation/`에 준비하고 기존 파일을 보존한다.
과거 `live`라는 폴더 이름은 새 유료 실행을 의미하지 않는다. pytest는 저장 결과 재생/합성 테스트와 구별해 해석한다.

```powershell
python -m pip install -r requirements-dev.txt
python scripts/prepare_test_fixtures.py
python -m pytest -q -rs
python scripts/validate_corpus.py --output-dir .local_validation/fresh_offline
# 아래만 실제 CLOVA 사용 가능: 새 키, 문서 전송 승인 및 비용 확인 후 실행
python scripts/validate_corpus.py --live --cases D00 D02 D13 D14 D15 D16 --output-dir .local_validation/fresh_live
```

## 5. 설정·보안·저장소 관리

`.env.example` 또는 `.streamlit/secrets.toml.example`를 복사해 **본인의 새로 발급한 키**를 로컬 파일에 입력한다.
Python 3.10에서는 `.env`를 사용하는 위 빠른 시작을 권장한다. 실제 설정 파일은 Git에서 제외된다.

**과거 기준 커밋의 예제 파일에 실키가 포함되어 있었다. 현재 파일에서는 제거했지만 기존 Git 이력은 보존한다.**
키 발급처에서 폐기·재발급해야 하며 이 업데이트를 키 무효화/과거 기록 정리 완료로 이해하면 안 된다.
강제 push나 과거 커밋 재작성은 수행하지 않는다.

실제 수신함, 메일 계정 인덱스, 판정 상태, 미리보기 사본, 실행 보고서, 가상환경은 코드와 분리한다.
이번에 이미 추적되던 런타임 폴더는 **Git 추적에서만 제외**했으며 개발 PC의 실제 파일은 보존한다.
새 clone은 기존 사용자의 문서함이나 판정 이력을 복사하지 않고 빈 상태로 시작한다.

원본 `db045c5`의 Git 이력과 폴더 구성은 유지하며 최신 변경은 그 다음 커밋으로 올린다.
자동화, 새 PR, 별도 원격 작업 브랜치는 이번 게시에 포함하지 않는다.
