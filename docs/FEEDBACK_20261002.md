## 사용자가 결과를 비교하는 법

1. 동일한 최신 SP와 허가서를 선택해 **검수 진행**을 누른다. 화면의 기존 저장 결과와 새 검수는 다르다.
2. 최종 화면의 **집계 기준 · 관련 검사 · 검수 파일/버전**을 펼친다.
3. SP와 허가서의 SHA256이 각각 같은지 확인한다. 이름이 같아도 내용이 다르면 해시가 달라진다.
4. 릴리스·엔진 SHA256·MD SHA256 및 실행 방식이 같은지 확인한다. 오프라인과 CLOVA 연동 결과는 구분한다. CLOVA 연동은 검증된 동일 요청의 응답 캐시를 사용할 수 있다.
5. 같은 조건인데 차이가 있으면 총계뿐 아니라 다른 시험명·기준·결과·판정 이유를 대조한다. 해시 일치만으로 모델 비결정성이나 추출 환경 차이까지 없다고 보장하지 않는다.

엔진 지문은 설치 경로와 CRLF/LF 차이를 제외한 Python·MD 소스로 계산한다. 파일 해시는 원문 바이트 기준이다. 새 결과 메타데이터는 기존 추출 환경 기록과 함께 보존되며, 검수 도중 SP/허가서가 변경되면 결과 완료를 거부한다. 실제 키·로컬 절대 경로는 새 사용자용 검수 정보에 노출하지 않는다.

## 번호와 범위

- 최신 요구사항 번호: B.14는 정성적 불검출 표기 대응, B.15는 복합 조건, B.21은 제조량·사용량·분량·투입량 구분, B.22는 SP와 허가 기준의 단위·수치 일치이다.
- 과거 파일 이름의 B.22를 자동으로 현재 B.22 실행 규칙으로 해석하지 않는다. 판정은 문서 내용과 실행 MD를 사용한다.
- C.1의 필수 공정 누락 연결은 전체 임의 제조요약도의 연결·순서 해석을 완성했다는 뜻이 아니다.
- D15의 X는 등록된 제품·시험·기준 범위에서만 해석한다. 다른 모든 시험에서 불검출로 간주하지 않는다.

## 검증 기록

- Python 3.14.7 전체 자동시험: **1693 passed / 7 skipped / 실패 0** (740.50초). 7개는 기존 미구현 단계 재개 계약이며 통과로 포함하지 않았다.
- 현재 D00~D16 실제 PDF 재추출 오프라인 17개: 기대 규칙·개별 실패·양성 대조 누락 0. 오프라인의 의미판정 보류는 CLOVA 연동 결과와 구분한다.
- 현재 D00~D16 CLOVA 연동 17개: 모든 기대 조건 통과. 기존 동일 요청 응답 캐시를 사용했으며 17개 전부 새 유료 추론을 받았다는 뜻은 아니다.
- 각 원본 SHA256, 실행 중 엔진 변경 없음, 개별 시험·표 행 상태 및 전체 집계를 대조해 **17/17 v107 결과와 동일**함을 확인했다. 판정 조건을 바꿔 보류를 숨기지 않았다.
