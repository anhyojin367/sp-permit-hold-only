# 규칙 회귀 로그와 RAG/MD 운영 가이드

## 1. 목적

이 문서는 다음 두 가지를 한 흐름으로 관리하기 위한 운영 기준이다.

1. `overall.md` 또는 판정 코드가 바뀔 때 기존 규칙의 결과가 사라지거나 변하지 않았는지 확인한다.
2. 제약 담당자가 추가한 RAG 자료와 회사·제품 MD가 실제 판정 요청에 어떻게 사용되는지 추적한다.

회귀 로그는 관측 기능이다. 기존 판정 결과를 바꾸거나 UI 집계를 다시 계산하지 않는다.

## 2. 판정 구조

```text
SP PDF
  ├─ 추출기: 본문, 표, 제조정보, 시험정보를 구조화
  ├─ 결정적 검증기: 수치·날짜·제조번호·공정 순서 등을 코드로 판정
  ├─ 공통 RAG: 약전·생기법·단위 자료에서 관련 근거 검색
  ├─ 도메인 MD: overall + 회사 + 제품 체크리스트 병합
  ├─ LLM: 결정적 규칙으로 확정되지 않은 시험의 의미를 보조 판정
  ├─ 허가서: 연결된 제품 허가서를 사용해 보류 항목 추가 검토
  └─ 회귀 로거: 위 결과와 사용 근거를 PDF별 Excel에 추가
```

중요한 책임 구분:

- 코드는 규칙을 실행한다.
- RAG는 관련 근거를 검색한다.
- MD는 LLM이 확인할 관점과 주의사항을 제공한다.
- LLM은 제공된 시험정보·근거·MD를 해석한다.
- MD 문장만으로 새 Python 검증기가 자동 생성되거나 실행되지는 않는다.

예를 들어 `overall.md`에 `페이지 번호 연속성을 검증한다`를 적어도
`page_number_validator.py`와 파이프라인 연결 코드가 없으면 정확한 페이지 판정은 실행되지
않는다. 회귀 Excel은 이런 상태를 `미구현`으로 표시한다.

## 3. PDF별 회귀 Excel

### 3.1 생성 위치와 파일명

판정이 완료되면 다음 파일이 자동 생성된다.

```text
OUTPUT/<PDF파일명>__<PDF SHA-256 앞 12자리>__rule_regression.xlsx
```

같은 이름의 다른 PDF는 해시가 다르므로 서로 다른 파일에 기록된다. PDF 한 개에는 Excel
한 개만 사용하며, 새로운 판정 실행은 같은 파일의 이력 행으로 추가된다.

환경변수 `SP_RULE_REGRESSION_LOG=0`을 설정하면 기록만 비활성화된다. 판정 기능에는 영향을
주지 않는다.

### 3.2 시트 구성

| 시트 | 내용 |
|---|---|
| `회귀요약` | 정답지와 실행별 규칙 집계 |
| `판정상세` | 시험·제조정보의 개별 판정 상세 |
| `규칙카탈로그` | `overall.md`의 각 규칙 문장, 담당 코드, 구현 상태 |
| `RAG_MD사용내역` | 사용한 RAG 자료, MD 파일, 모델, 지문 |

### 3.3 회귀요약 행

| 행 | 의미 |
|---:|---|
| 4 | 칼럼명 |
| 5 | 정답지 |
| 6 이후 | 실행 이력 |

주요 규칙 칼럼:

- 시험기준/결과 비교
- 문서 구조/추적성
- 페이지 번호 검증
- 제조번호 비교
- 제조일자 비교
- 제조량 비교
- 시험일 허용구간
- 날짜 선행관계 비교
- 참고 문서 적용
- 보류 원칙

값은 `충족/불충족/보류` 순서의 축약값이다.

```text
123/1/0
```

위 값은 충족 123건, 불충족 1건, 보류 0건을 의미한다. 전용 검증기가 없으면 숫자를
추정하지 않고 `미구현`, 실행되지 않았으면 `미실행`, 예외가 발생하면 `실행오류`로 남긴다.

### 3.4 정답지 운영

새 Excel의 정답지 행은 상태가 `입력 대기`이고 판정값 칸은 모두 비어 있다. 제약 담당자가
확정한 값을 `충족/불충족/보류` 형식으로 직접 입력하면 이후 실행부터 입력된 항목만
`정답지대비` 열에서 비교한다. 비어 있는 항목은 비교 대상에서 제외한다.

필요한 경우에만 최신 실행값을 정답지로 복사:

```powershell
python scripts/rule_regression_log.py set-gold `
  "OUTPUT\<파일명>__<해시>__rule_regression.xlsx" `
  --status "확정"
```

파일 목록 확인:

```powershell
python scripts/rule_regression_log.py list --output OUTPUT
```

전체 인덱스 재생성:

```powershell
python scripts/rule_regression_log.py index --output OUTPUT
```

정답지 행은 판정 실행에서 자동으로 채우거나 덮어쓰지 않는다. 사람이 Excel에서 값을
수정해도 그 값이 유지된다. 이전 버전이 자동 생성한 `초안` 정답지는 새 형식으로 열 때
`입력 대기`와 빈 판정값으로 변환되지만, 사람이 입력한 정답지는 보존된다.

`회귀요약`에는 전문가가 읽고 비교하는 열만 표시한다. PDF 해시, 실행 ID, 코드/RAG/MD
지문과 LLM 호출 수 같은 기술 정보는 요약 열에 표시하지 않으며, 중복 방지와 내부 감사에
필요한 값은 상세 시트에서 관리한다.

### 3.5 실행 ID와 중복 방지

다음 항목을 묶어 실행 ID를 만든다.

- 입력 PDF 해시
- 연결 허가서 해시
- 주요 판정 코드 지문
- RAG 자료 지문
- 선택된 MD 지문
- LLM 모델명, 호출 수, 성공 수, 마지막 오류 지문

같은 조합을 다시 열거나 Streamlit 캐시에서 재표시한 경우에는 같은 행을 중복 추가하지
않는다. 코드, RAG, MD, 모델 또는 입력 파일이 바뀌면 새 행이 추가된다.

## 4. 현재 RAG의 실제 구조

현재 `sp_pdf_judger/rag.py`는 외부 벡터 데이터베이스를 사용하지 않는다. 시작 시 자료를
메모리에 읽고 다음 두 TF-IDF 유사도를 합산하는 로컬 검색기다.

- 단어 1~2그램: 65%
- 문자 2~5그램: 35%

문자 검색은 OCR 오탈자, 조사, 단위 기호 차이를 완화한다. 즉 현재 시스템에서 “벡터
데이터베이스”라고 부르는 부분은 운영 개념상 지식 검색 계층이며, 구현체는 영구 DB가 아닌
메모리 TF-IDF 인덱스다.

### 4.1 적재 자료

- 프로젝트 루트 `ucum_rag_docs.json`
- 프로젝트 루트 `ucum_rag_image_units_ui_micro.jsonl`
- 프로젝트 루트 `ucum_rag_image_units_enriched.jsonl`
- 프로젝트 루트 `TableOfExampleUcumCodesForElectronicMessaging.xlsx`
- `rag_data` 바로 아래의 `*.pdf`

`rag_data` PDF는 현재 하위 폴더를 재귀 검색하지 않는다.

### 4.2 검색과 LLM 전달

시험명, 시험기준, 시험결과를 조합해 검색 질의를 만든다. 검색 결과는 자료명, 페이지,
청크 본문과 함께 최대 후보 집합으로 LLM 프롬프트에 전달된다.

RAG 결과는 다음 역할을 한다.

- 단위와 기호 해석
- 약전·생기법 등 공통 기준 근거 제시
- 결정적 코드가 확정하지 못한 시험의 해석 보조

RAG 문서 자체가 Python 검증기를 실행하거나 확정 판정을 강제로 덮어쓰지는 않는다.

### 4.3 자료 추가

PDF:

1. 텍스트 선택이 가능한 승인 자료를 `rag_data` 바로 아래에 둔다.
2. 파일명에 자료명과 버전을 명시한다.
3. Streamlit을 재시작한다.
4. 회귀 Excel의 `RAG_MD사용내역` 또는 `ProcessingResult.metadata.rag_sources`에서
   적재 여부를 확인한다.

JSON/JSONL/XLSX:

- 기존 로더가 인식하는 후보 파일명과 필드 구조를 따라야 한다.
- 새로운 파일명이나 표 구조를 사용하려면 `config.py`와 `rag.py`에 로더를 추가한다.
- 단순히 임의 파일을 폴더에 복사하는 것만으로는 자동 적재되지 않는다.

제품별 허가서는 전역 `rag_data`보다 선택 문서의 `PermitPdfStore`로 연결하는 것이 안전하다.
전역 RAG에 제품별 허가서를 두면 다른 회사·제품 검색에 섞일 수 있다.

## 5. 도메인 MD가 LLM에 사용되는 방식

### 5.1 선택 순서

`sp_pdf_judger/domain_details.py`는 활성 MD를 읽고 문서의 회사명·제품명 별칭과 비교한다.

```text
overall.md 전체 1개
  + 가장 잘 맞는 회사 MD 1개
  + 가장 잘 맞는 제품 MD 1개
```

예:

```text
overall.md
companies/gc_biopharma.md
products/albumin.md
```

세 문서는 `overall → company → product` 순서로 병합된다. 선택된 파일과 지문은 결과
메타데이터 및 회귀 Excel에 남는다.

### 5.2 LLM이 받는 정보

LLM 호출에는 대체로 다음 내용이 함께 들어간다.

- 시험명
- 시험방법
- 시험기준
- 시험결과
- 결정적 판정 결과 또는 보조 판정 지시
- RAG 검색 근거
- 연결 허가서 근거
- 전체·회사·제품 MD 컨텍스트

MD의 역할은 다음과 같다.

- 확인할 비교 관계를 빠뜨리지 않도록 지시
- 회사·제품별 용어와 단계 별칭 설명
- 제조량과 사용량, 제조일과 분병일처럼 혼동하기 쉬운 필드 구분
- 사람 확인이 필요한 예외와 보류 원칙 설명

### 5.3 MD만으로 가능한 것과 불가능한 것

MD만으로 비교적 잘 가능한 일:

- 이미 추출된 필드의 의미 구분
- LLM 보조 판정 시 확인 관점 추가
- 회사·제품별 용어와 예외 설명

코드가 필요한 일:

- PDF 좌표나 페이지 번호를 정확히 추출
- 모든 페이지의 연속성·중복·누락을 결정적으로 검증
- 새로운 표 방향을 행·열 구조로 변환
- 특정 필드의 집계 방식을 변경
- UI 카운트나 제조단계 매핑을 확정적으로 변경

따라서 새 규칙을 추가할 때는 먼저 “이미 추출된 텍스트를 해석하면 되는가”와 “새 구조
추출·정확 계산이 필요한가”를 구분한다.

## 6. 새 규칙 추가 절차

정확한 새 규칙은 다음 순서로 추가한다.

1. 제약 담당자가 규칙, 적용 범위, 근거, 정상·오류 예시를 정의한다.
2. 추출 필드가 있는지 확인한다.
3. 없으면 추출기 또는 OCR 후처리를 추가한다.
4. 결정적 검증이 필요하면 `<규칙명>_validator.py`를 추가한다.
5. `pipeline.py` 또는 관련 검증 흐름에 연결한다.
6. 대표 정상·오류 문서 테스트를 추가한다.
7. `overall.md`, 회사 MD 또는 제품 MD에 검수 관점을 기록한다.
8. PDF별 회귀 Excel에서 기존 정답지와 비교한다.

페이지 번호 규칙 예:

```text
PDF/OCR에서 인쇄 페이지 번호와 실제 PDF 인덱스 추출
→ page_number_validator.py에서 누락·중복·역순·목차 예외 판정
→ ProcessingResult에 결과 저장
→ UI 및 회귀 Excel에 집계
→ overall.md에는 검증 목적과 예외를 설명
```

MD에 페이지 번호 문장만 추가하는 것은 위 구현을 대신하지 않는다.

## 7. 제약 담당자와 AI 담당자의 변경 절차

제약 담당자:

- 회사·제품별 정상 흐름과 중요 비교 항목 정의
- 출처, 버전, 시행일, 승인 상태 기록
- 정상 PDF와 의도적으로 오류가 있는 PDF의 정답지 확정
- 새 규칙의 예외와 보류 조건 승인

AI 담당자:

- 추출기, 검증기, RAG 로더와 파이프라인 구현
- MD 별칭 매칭 및 LLM 컨텍스트 조립
- 회귀 Excel 생성과 실행 지문 관리
- 전체 대표 문서 회귀 테스트

권장 순서:

```text
회의 결과 기록
→ MD/RAG/코드 중 반영 위치 결정
→ 기준 API 코드에서 대표 PDF 실행
→ 회귀 Excel 정답지 비교
→ 기존 제품 회귀 확인
→ 로컬 LLM 코드에 동일 변경 이식
→ 같은 PDF와 정답지로 재검증
```
