# 허가 원문 소유 범위 (v77, 조건 판정의 선행 기반)

기존 검색용 `PermitChunk.text`는 상위 절에 하위 시험 본문을 포함한다. 이것을
상위 공통조건과 각 하위 조건으로 다시 합치면 같은 근거를 여러 번 셀 수 있다.
새 `owned_spans`는 추출 당시의 위치로 본문을 나눠 실제로 쓰인 문자를 한 문단에만 연결한다.
똑같은 문장이 다른 위치에 실제로 두 번 있으면 둘 다 보존한다. 문자열 중복 제거가 아니다.

## 유지한 동작

- 기존 `text`, 페이지 범위, 검색, 운영27개 MD 및 UI 레이아웃은 그대로다.
- 새 전체 근거 목록은 별도 진단 경로다. 이를 운영 필수시험 목록이나 면제 판단으로 사용하지 않는다.
- leaf(말단 문단)는 시험 의무와 같은 뜻이 아니다. 절차, 정보, 날짜 이력도 포함될 수 있다.

## 근거 계약

`build_permit_ownership_inventory(store)`가 모든 문단을 열거한다. top-k 검색을 쓰지 않는다.
각 문단은 고유 ID, 상위 ID/전체 조상 ID, 직접 소유한 문장, 원문 구간을 가진다.
구간은 **clean_text로 정규화된 물리 페이지 텍스트**의 시작 포함/끝 제외 문자 위치다.
PDF 바이트 위치·화면 좌표가 아니다. PDF SHA256도 별도로 고정하여 원본 변경을 확인한다.
ID는 전체 추출 문서·파일명·위치·내용에 묶이고, 상위 문장이나 개정 이력이 바뀌어도 달라진다.

- 모든 비공백 원문 문자에 소유자가 정확히 하나인지 검사한다.
- 문서/구간/문단 ID, 인용, 순서, 상위 번호·경로를 대조한다.
- 페이지 누락·빈 페이지·중복/역순·추출 오류·구형 위치 없는 문단은 오류로 남긴다.
- 독립 표지/제품정보, 전역 안내, 날짜 이력을 `unscoped_ids`에 유지한다. 삭제하거나 자식 모두에 적용하지 않는다.
- 기존 파서가 `2024.06.19`를 절 번호처럼 분리해도 새 목록에서는 유효한 날짜 항목으로 구별한다.
  날짜 항목을 상위 의무로 쓰지 않으며 개정 관계가 확정되었다고 간주하지 않는다.
- 복수 허가서는 목록에 남기되 개정 관계 미지원 오류를 반환한다. 다른 파일을 조용히 합치지 않는다.
- 문서 안의 명령문도 인용 데이터일 뿐이며, 이 경로는 LLM이나 판정 상태를 생성하지 않는다.

`errors`가 하나라도 있으면 후속 조건 판정 입력으로 사용할 수 없다. 오류가 없어도 의미 해석,
전체 공통조건 적용, 필수 의무 승인까지 끝난 것은 아니다. OCR 누락/레이아웃 정확성을 이 검사만으로 보증하지 않는다.

## 재현과 관찰

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_permit_source_ownership.py tests/test_permit_ownership_pdf.py
.\.venv\Scripts\python.exe scripts/prove_permit_ownership.py
```

합성 PDF는 `.local_validation/permit_ownership_proof`에만 생성한다. 3페이지에서 상위/하위 중복,
실제 반복 문장, 페이지를 넘는 본문, 같은 이름의 다른 단계, 날짜 이력, 독립 제품정보를 검증한다.
판정이나 CLOVA 호출을 수행하는 시험은 아니다.

제공 허가는 23물리쪽/147기존 문단, 276독립 원문 구간이다. 기존 검색 필드 전체의 고정 해시
`1af8d1fa8d0b23d6e4184533976dda831102d6e7c47b5a018833f6091e353591`을 변경 전후 대조한다.
`경우`가 직접 소유된 문단은3개다(유정란 접종, 나노파티클/완제 SE-HPLC). 이를 조건부 필수시험3개로 해석하지 않는다.
