# 화면 제보 원인과 수정 (2026-09-27)

## 1. 엔도톡신: 기준 출처가 다른 두 질문

D02 물리18쪽의 SP 시험기준은 **820 EU/mL 미만**, 결과는 **760 EU/mL**이다. SP 기재 기준만 보면 충족한다. 그러나 연결 허가서 물리14쪽(인쇄16/60)의 Component B 엔도톡신 기준은 **820 EU/mg of protein 미만**이다. 서로 다른 분모를 숫자만 비교해서는 허가 기준 충족을 확정할 수 없다.

SP 물리17쪽에는 단백질함량680 μg/mL도 있지만, 자동 환산에는 적용 가능한 환산식·같은 시료 및 측정 기준의 연결 근거가 필요하다. 인접 시험이라는 이유만으로 환산하거나 정상본이라는 이름 때문에 합격시키지 않았다. 최종 이유에 SP 단독 비교와 허가 우선 보류를 함께 표시하도록 보완했다. 원본 숫자/단위를 수정하지 않았다.

## 2. 무균시험: 판정은 있었지만 화면이 숨겼음

D02 물리19쪽 나노파티클 무균시험은 원문 결과란에도 '균이 확인되지 않아야 함'이라고 되어 있다. 실제 관측 결과 대신 요구 문장이 반복되므로 판정 엔진은 보류했다. 하지만 UI가 `comparison_completed=false`인 판정의 이유와 상태점을 모두 숨겨 빈 카드처럼 보였다.

이제 근거가 있는 보류는 비교 완료 여부와 관계없이 기존 이유 상자와 주황색 점으로 표시한다. 아직 판정하지 않은 레코드에 가짜 상태를 붙이지 않는다.

## 3. 결과의 제조번호: 페이지 머리말 연결 오류

CHO 마스터 마이코플라스마 결과 뒤에 붙었던 SKY-M220805-001은 다음 물리6쪽의 상단 머리말이다. CHO 제조용 무균 및 나노파티클 폴리소르베이트80 결과에서도 같은 유형의 혼입을 확인했다. OCR이 숫자를 잘못 읽은 문제가 아니라, 페이지 경계에서 머리말을 앞 시험에 이어 붙이는 추출 후처리 문제였다.

동일 프로토콜 제목과 제조번호가 여러 페이지의 같은 상단 위치에 반복되는 경우만 머리말로 분리한다. 원문 raw JSON과 `extraction_cleanup`에 원문/쪽/위치/분리 사유를 보존한다. 표지와 본문의 제조번호, 단일·불명확한 후보는 삭제하지 않는다. D02의 의도적인31쪽 표기 오류도 그대로 검출한다.

## 4. 지연과 시뮬레이션

- 이전에는 실제 PDF 추출/CLOVA 판정을 동기로 모두 기다린 뒤 화면을 그렸다. 이후 노드별 긴 애니메이션까지 별도로 기다려야 했다.
- `sp_review_jobs.py`는 동일 입력의 판정을 하나의 백그라운드 작업으로 공유한다. 작업은 프로세스당 하나씩 실행해 API 중복/경쟁을 줄인다. 실패는 화면 갱신만으로 재시도하지 않는다.
- 기존 진행 영역에 현재 단계·시험 번호·경과 시간을 표시하고, 목록 복귀 시에도 작업을 유지한다. 새 프로세스로 재시작하면 실행 중 작업의 메모리 상태는 이어지지 않는다.
- 실제 판정 산출물과 요약이 준비된 뒤에만 기존 최종 이동 버튼을 활성화한다. 애니메이션은 판정의 근거가 아니며, 스킵해도 결과가 바뀌지 않는다.
- 애니메이션 목표12초,14초 안전 종료. 외부 GSAP 로딩 실패 시 같은 계산 결과를 정적으로 표시한다. 원래 카드·색상·배치는 유지한다.

QA 합성15단계에서 실제 재생12.014초, 표시 카운트 전체 일치 및 브라우저 오류0을 확인했다. GSAP가 없는 경우 Start 즉시 완료 그래프와 링크가 나타났으며, 대기 작업 중 버튼 조작도 정상 완료됐다. 이는 합성 UI 실패모드 시험이고, D00~D12 실문서 판정과는 별도다.

## 5. 후속 v85: 이유 문장과 최종 상태를 혼동한 집계

v84의 실제 D02 애니메이션에서 Component B가 충족11/보류0으로 표시되는 추가 오류를 발견했다. 엔도톡신의 최종 상태는 보류인데, 단계 집계와 CSV가 설명 중 'SP 기재 기준만 비교하면 충족입니다'를 먼저 해석해 충족으로 바꿨다. 남은 보류가 문서 공통 항목으로 이동하면서 전체125/2/2만 대조하는 검사에는 드러나지 않았다.

v85에서는 단계 카드·CSV·색상 표시가 명시된 최종 상태를 우선한다. 배치별 상태도 부모 판정이나 설명으로 바꾸지 않는다. 상태 필드가 없는 과거 데이터에 한해서 기존 이유 해석을 유지한다. 이전 화면 캐시를 재사용하지 않도록 버전도 올렸다. 판정 규칙·CLOVA 프롬프트·원문은 바꾸지 않았다.

새 검사는 설명이 최종 상태와 충돌하는 경우, 배치별 보류, D00~D12의 오프라인/CLOVA 저장 결과26개를 모두 다룬다. 실제 절 번호를 기준으로 독립 집계하여 단계별 카드·시뮬레이션 CSV·시험별 내보내기 CSV와 대조한다. 이것은 v84 판정을 v85 표시 코드로 재검증한 것이며, 새로운 전체 유료 API 시험으로 계산하지 않는다.
