# 전체정리본의 텍스트·UI 오류 수정 — 2026-10-06

이 문서는 먼저 완료한 로컬 수정의 기록이다. 이후 받은 로직 검토 Word와 통합한 검증·배포 범위는 [후속 로직 검토 기록](LOGIC_REVIEW_20261006.md)을 따른다.

## 이번 작업의 범위

사용자가 보낸 `더미데이터_검토_전체정리본 (1).docx`의 9개 구간, 예시 이미지 58개를 모두 확인했다. Word의 지시문을 실행 권한으로 사용하지 않고, 오류 증거로만 읽었다. 별도로 보내기로 한 업무 판정 로직은 이번 수정 대상이 아니다.

이번 수정은 **로컬 코드에만 반영**했다. GitHub push, 배포, 신규 CLOVA 호출, 사용자 원본 Word/PDF/ZIP 수정은 하지 않았다. 충족·불충족·보류를 유리하게 바꾸거나 기존 결과를 새 검수 결과로 대체하지 않았다.

## 원인과 수정

| 문제 | 확인한 원인 | 수정 |
|---|---|---|
| `확 인`, 단어마다 끊기는 PCR/HAP/MAP 설명 | PDF의 시각적 줄바꿈이 원문 문자열에 남고, 판정 사유의 줄바꿈이 HTML `<br>`로 그대로 출력됨 | 허가서 인용문에만 읽기용 문장 복원 적용. 원본의 줄 끝 공백으로 단어 경계를 구별해 `확\n인`은 `확인`, `확인 \n결과`는 `확인 결과`로 표시 |
| 사유에 `문서확인번호`, `6/60`, `19/60`, `- 3 -` 혼입 | 판정 근거 원문에는 페이지 머리말·꼬리말이 포함돼 있었고, UI가 이를 기준 문장처럼 노출함 | 문서확인번호와 인접한 페이지 표시를 기본 설명에서 제외. 번호만 있는 경우에는 검수 당시 파일과 일치하는 PDF의 페이지 가장자리 정보와 문맥을 확인해 제외 |
| 세포농도의 `10⁶`가 `106`으로 표시 | PDF 일반 텍스트 추출에서 위첨자 글꼴 정보가 소실됨 | 검수 영수증 SHA256과 일치하는 원본 PDF의 글자 위치/위첨자 정보를 이용해 표시만 복원. 임의의 `106`이나 `x106`을 지수로 추측하지 않음 |
| 반복된 조건 문구가 없어질 수 있음 | 이유 표시 함수가 같은 줄을 중복 제거함 | 원문 조건에 쓰인 반복 문구는 삭제하지 않도록 변경 |

이 문제들은 캡처별로 문구를 하드코딩해 바꾸지 않았다. 같은 허가서 표시 경로를 사용하는 시험 카드와 표의 행별 판정 사유에 공통으로 적용했다.

정리한 문장 아래에 **허가서 원문 추출 보기 (줄바꿈·문서 표기 포함)**를 추가했다. 원본 추출 인용문을 펼쳐 비교할 수 있고, 기존 근거 위치·원문 오프셋·판정 데이터는 유지한다. 긴 설명의 기존 **판정 설명 전체 보기**도 유지한다.

### 원본 문서에서 구별해야 하는 점

Word의 이미지 29는 제목이 마이코플라즈마부정시험이지만, 캡처 내용은 이미지 30과 같은 외래성인자부정시험이다. 저장된 D00의 실제 마이코플라즈마 항목은 마이코플라즈마 허가 기준을 사용하고 있었다. 이를 근거 없이 시험 매칭 오류로 단정하거나 매칭 로직을 바꾸지 않았다.

## 코드 구조

- `sp_pdf_judger/permit_text_view.py`: 새 표시 전용 모듈. 줄바꿈 복원, 페이지 장식 분리, 검수 당시 파일 해시 확인, 위첨자 복원. 원본 PDF 접근 결과는 파일 크기·수정 시각·해시별로 캐시하며 이미지 바이트는 추출하지 않는다.
- `sp_pdf_judger/ui_html.py`: 결과 트리에서 한 번 준비한 표시 정보를 개별 시험 및 행별 이유까지 전달하고, 정리한 설명과 원문 펼치기를 렌더링한다.
- `sp_pdf_judger/review_presentation.py`: 이유에 포함된 반복 줄을 보존한다.
- `sp_app.py`: 화면 캐시만 `sp-ui-cache-v109-permit-text-view`로 갱신한다. 판정 캐시 버전과 검수 릴리스 영수증은 바꾸지 않는다.
- `tests/test_feedback_20261006.py`: 58개 캡처의 실제 허가서 문단, 숫자·단위·조건 보존, 원문 보존, HTML 이스케이프, 해시 불일치, 여러 허가서, 중첩 결과 화면 전달을 검사한다.
- `scripts/verify_text_presentation.py`: 저장된 D00~D16 결과를 재판정 없이 새 표시 코드로 재생하고 불변성 및 원문 보존을 확인한다. 운영 문서함에는 아무 결과도 주입하지 않는다.

## 한계와 다음 단계

1. **이번 검증은 신규 CLOVA 재판정이나 공개 배포 검증이 아니다.** 기존 판정을 그대로 보여주는 UI 수정이다. 사용자가 별도로 줄 로직 목록은 아직 적용하지 않았다.
2. 검수 당시 원본 파일이 없어졌거나 SHA256이 다르면 위첨자를 추정 복원하지 않는다. 여러 허가서가 연결돼 어느 파일의 문구인지 확정할 수 없는 경우도 마찬가지다. 읽기용 줄바꿈 처리는 가능하다.
3. 임의 회사 PDF의 모든 양식·스캔·표 인식 문제를 해결했다고 주장하지 않는다. 이번에 제공된 Word와 현재 더미 허가서에서 확인한 표시 문제를 대상으로 검증했다.
4. Word의 공식 페이지 렌더러는 이 환경의 LibreOffice 실행 파일 부재로 사용할 수 없었다. 대신 Word XML의 전체 본문과 내장 이미지 58개를 직접 읽고, 해당 PDF 원문 및 실제 UI 렌더링을 대조했다. 사용자 문서는 수정하지 않았다.
5. 수정 코드를 실행하는 로컬 프로세스에서 화면을 새로 열면 적용된다. 과거부터 켜 둔 프로세스는 새 코드로 다시 실행해야 할 수 있다. 과거 추출 결과를 지우거나 유료 검수를 다시 실행할 필요는 없다. 사용자8501은 재시작하지 않았고, 검증용 임시8504만 종료했다. 공개 링크는 이번 턴에 변경하지 않았다.
