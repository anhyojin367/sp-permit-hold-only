# 시뮬레이션 준비와 화면 반응성

## v98: 지원하지 않는 구조를 정상 공정도로 표시하지 않기

PDF에서 여러 `flowchart` 레코드가 나오면 예전에는 첫 번째만 반환했다. 이제 다중 공정도임을 알리고 중단한다.
서로 동일해 보이는 레코드나 빈 두 번째 공정도도 자동 삭제/병합하지 않는다. 반복 표시인지, 다른 제조 공정인지,
다음 페이지로 이어지는 것인지 판단할 근거가 아직 없기 때문이다. 이는 **다중 공정도 지원 완료가 아니라 안전한 제한**이다.

공정도 레코드는 있는데 데이터가 없거나 nodes/edges가 올바른 목록이 아니면 '공정도 없음'으로 바꾸지 않는다.
명시적인 단일 빈 목록(nodes=[], edges=[])과 아예 공정도 레코드가 없는 경우만 기존 미발견 처리다.
정규화 후 동명 단계, 중복 연결선, 존재하지 않는 노드로 가는 선, 순환·재작업 연결도 명시적으로 중단한다.
연결선의 노드 ID는 문자열 또는 정수만 받는다. `true`/`1.0`을 정수 노드1로 취급하지 않는다.
유효한 다른 루트가 있어도 별도 연결 묶음 속 순환을 놓치지 않는다. CSV 추정 구조로 오류를 숨기지 않는다.

정상적인 비순환 분기/합류에서는 이전의 방문 순서 기반 배치를 **모든 선행 공정이 처리된 후 배치하는 방식**으로 바꿨다.
예를 들어 A→D와 A→B→C→D가 함께 있으면 D는 C 이후, D→E의 E는 D 이후에 놓인다.
입력에 노드가 어떤 순서로 나와도 이 관계가 유지된다. 독립적인 비순환 공정 묶음이나 고립 노드는 허용하며
그 사이에 원문에 없는 연결선을 만들지 않는다. 기존 D02의 정상 배치/숫자를 바꾸려는 수정이 아니다.

실패는 기존 그래프 준비 오류 영역으로 전달되고 화면 재실행만으로 새 작업을 반복하지 않는다.
합성 자료로 실제 작업 관리자/Streamlit 오류 분기를 확인하며, 정상 더미 원본의 새 추출과 실제 D02 UI는 별도 검증한다.
최종 시험/브라우저/불변 감사 상태는 `WORK_STATUS.md`를 따른다.
추출기 내부에서 이미 삭제·합쳐진 공정이나 잘못 추정된 화살표까지 이 자료형/그래프 검사가 증명하지는 않는다.

## v97: 제조 공정과 공통 판정 숫자를 구별

이 절은 아래 v96의 **구조 선택 방식 유지** 설명보다 우선한다. 현재 최종 시험 상태는 `WORK_STATUS.md` 참조.

기존에는 ‘문서 공통·기타 검증’도 제조 단계로 연결했다. PDF9노드보다 CSV10노드가 많다는 이유로
실제 PDF 연결선 대신 단계명으로 추정한 연결선이 선택될 수 있었다. 이제 다음처럼 구성한다.

- `process`: PDF/CSV의 실제 공정 단계. CSV의 모든 공정명이 PDF와 일대일 대응하면 PDF 연결선을 사용한다.
- `document_check`: 내보내기에서 만든 ‘문서 공통·기타 검증’/‘문서공통’. 숫자는 표시하되 제조 연결선은 없다.
- `unassigned_check`: ‘단계 미분류 시험’. 임의로 특정 공정에 배정하지 않고 숫자를 별도로 표시한다.

공통/미분류 상자는 기존 마지막 열에 남는다. HTML/CSS·Start·카운터·최종 링크는 바꾸지 않았지만,
공통 상자로 향하던 연결선을 제거하고 실제 PDF가 선택되면 CSV 추정 경고가 없어지는 것은 의도한 변화다.
‘공통’이라는 글자가 포함됐다는 이유만으로 모르는 공정을 제외하지 않으며 명시적인 집계 이름만 구별한다.

PDF가 일부 공정을 담지 못하면 PDF를 우선하지 않는다. 기존 CSV 추정 표시와 출처 경고를 유지한다.
단계명 정규화 중복은 임의로 합치지 않고 중단한다. 직렬화 직전에도 요약의 모든 행이 한 번씩 매칭되는지 검사한다.
요약 숫자가 음수/비정수/누락이거나 합격·불합격·보류 합과 행 총계가 다르면0으로 바꾸지 않고 실패 처리한다.
전체행 자체와 각 행의 합을 대조하는 별도 무결성 검사까지 추가한 것은 아니다.

검증은 실제 D02 새 추출과 저장 D00~D12 결과26건의 그래프 매핑 재생으로 구분했다.
실제 D02는9공정/8연결+연결 없는 공통1개이며 기존125충족/2불충족/2보류/129를 보존한다.
26건 재생은 기존 오프라인13/기존 CLOVA13과 v96의 공정도 추출을 재사용하므로 새 유료 판정이 아니다.
단계 이름이 같다는 것만으로 모든 화살표 의미가 인증되지는 않는다. 다중 공정도, 순환/재작업, 동명 공정,
추출기 내부 연결선 누락과 복잡한 층 배치의 검증은 남아 있다. 변경은 판정 엔진/MD가 아니라 표시용 그래프 구성이다.

v95에서 바꾼 것은 **제조요약도 그래프를 준비하는 실행 위치**다. PDF를 읽는 알고리즘이나 판정 기준은 바꾸지 않았다.
v96에서는 그 다음 경계인 **PDF 추출 실패와 CSV 추정 구조의 출처**를 구분했다. 아래 v96 절을 함께 본다.

## 무엇이 달라졌나

기존에는 판정 결과가 이미 저장되어 있어도, 처음 시뮬레이션에 들어갈 때 화면 처리 안에서 PDF 제조요약도를 다시 읽었다.
v94 실제 D02에서는 이 구간이 약15.8초 걸렸다. 그동안 목록 복귀 버튼도 제때 처리되지 않을 수 있었다.

이제 `sp_simulation_jobs.py`의 별도 작업이 기존 그래프 로더를 실행한다. `sp_app.py`는 준비 안내와 경과 시간을 표시하고,
기존 목록 복귀 버튼을 사용할 수 있게 한다. 목록으로 돌아가거나 다시 진입해도 동일한 입력의 작업은 계속된다.
준비 전에는 가짜 그래프나 이전 문서의 최종 링크를 표시하지 않는다. 준비가 끝나면 기존 Start/시뮬레이션/최종 링크를 표시한다.

```text
실제 판정 요약 확보 → 그래프 준비 작업 시작 또는 기존 작업 연결
                           ├─ 준비 중: 안내·경과 시간·목록 복귀
                           ├─ 실패: 이유 표시, 명시적 재시도 대기
                           └─ 완료: 기존 Start/최종 결과 링크 표시
```

## 어떤 파일을 같은 입력으로 보나

- PDF, 명시적 판정 요약 CSV, 주변 요약 CSV와 단계 CSV 목록의 경로·크기·수정시각, 앱 버전을 작업 키에 포함한다.
- 실제 읽기 전과 끝난 후 다시 확인한다. 대기 중 또는 읽는 중 바뀌면 결과를 그대로 사용하지 않는다.
- 상태 인덱스의 옛 판정 요약도 현재 PDF의 크기·수정시각이 같고 실제 요약 파일이 있는 경우에만 빠르게 재사용한다.
- 로더가 밖으로 전달한 오류와 빈 그래프는 실패로 남는다. 화면 재실행만으로 반복하지 않고 기존 **검수 진행**을 다시 눌러 실패 작업을 재시도한다. 정상/진행 중 작업은 이 버튼으로 삭제하지 않는다.

이는 기존 방식과 같은 파일 크기·수정시각 확인이다. 같은 크기·같은 수정시각을 인위적으로 유지한 내용 변경까지 잡는 내용 해시 보증은 아니다.
같은 서버 프로세스 안의 중복 실행을 막지만 서버 재시작 후 작업을 이어가는 기능이나 여러 서버 사이의 잠금은 아니다.
작업 저장소는 판정용 저장소와 분리된 단일 작업자이며, 작업 내부에서 Streamlit이나 CLOVA를 호출하지 않는다.

## 검증 범위

자동시험은 입력 변경/누락, 대기 중·읽는 중 변경, 오류, 빈 그래프, 중복 실행, 실패 후 명시적 재시도를 검사한다.
실제 Streamlit AppTest에서는 그래프 로더를 의도적으로 지연시켜 목록 복귀·재진입·새 세션 연결을 검사했다.
이 합성 시험의 참조 검색/판정 결과는 fixture이며 API를 쓰지 않는다.

실제 브라우저 D02에서는 준비 안내를 본 뒤 **준비 중 목록 복귀 → 재진입 → Start → 최종 링크**를 직접 눌렀다.
최종125충족/2불충족/2보류/129건·허가1건과10단계 숫자는 기존 저장 결과와 같았다.
완료 후 다시 진입했을 때 Start 관찰은501ms였다. 단회 자동화 왕복을 포함한 관찰이며 모든 문서의 속도 보증이 아니다.
세부 전사/최종 감사와 전체시험 결과는 `WORK_STATUS.md` 및 `UI_VERIFICATION.md`를 따른다.

## 아직 해결하지 않은 것

첫 PDF 추출은 여전히 수행한다. 기존 판정 추출 레코드를 그래프에 안전하게 재사용하여 실제 계산량을 줄이는 작업은 이번 변경이 아니다.
유료 판정 지연, 서버 중단 작업의 단계별 복구, 허가서 전체 의미 검증 또한 별개다.
v95까지 내부 PDF 추출 예외가 `None`으로 숨겨져 CSV 추정 구조를 표시할 수 있었던 부분은 아래 v96에서 보완했다.
화면 레이아웃과 최종 뷰어는 유지했지만 준비 안내는 의도적으로 추가했으며 픽셀 단위 동일성 검사는 아니다.
기존 D02 캐시로 화면을 검증한 것을 새 CLOVA13개 통합시험이나 전체 과제 완료로 세지 않는다.

## v96: 추출 실패, 공정도 미발견, 추정 구조를 구별

`sp_flowchart_data.py`는 PDF 읽기/정규화/블록/레코드 추출 예외를 `FlowchartExtractionError`로 전달한다.
노드 식별자·이름이 누락/중복되거나 연결선이 존재하지 않는 노드를 가리키는 경우도 중단한다.
오류를 잡아 임의의 CSV 공정도로 바꾸지 않는다. 원래 예외는 원인으로 보존한다.
앱은 기존 오류 영역에 사유를 표시하며 기존 검수 진행을 통한 재시도 정책을 따른다.

읽기는 끝났지만 공정도가 발견되지 않은 경우, 연결선이 없는 경우, 기존 구조 선택 기준에서 PDF가 선택되지 않은 경우는 서로 다르다.
이 경우의 기존 CSV 추정 표시를 유지하되 다음 출처 정보를 그래프 JSON에 넣고 경고를 표시한다.

| 출처 | 의미 | 표시 |
|---|---|---|
| `pdf_extracted / selected_pdf` | PDF 추출 결과가 기존 선택 기준에 의해 사용됨 | 추가 경고 없음. 모든 실제 화살표의 정확성을 보증하는 인증은 아님 |
| `csv_inferred / no_pdf` | PDF를 제공하지 않음 | CSV 추정 연결선임을 경고 |
| `csv_inferred / pdf_not_found` | 추출 결과에서 공정도 노드 미발견 | 미발견 사유와 CSV 추정 경고 |
| `csv_inferred / pdf_without_arrows` | 노드는 있으나 연결선 미발견 | 연결선 미발견 사유와 CSV 추정 경고 |
| `csv_inferred / pdf_not_selected` | PDF 구조는 있지만 기존 선택 기준이 CSV를 선택함 | 선택 사유와 CSV 추정 경고 |

운영 앱과 단독 미리보기가 같은 출처 안내 함수를 사용한다. 출처가 없거나 알 수 없으면 확인 불가로 안내한다.
기존 뷰어 HTML/CSS와 배치는 그대로이며 경고 문구는 의도적인 추가 표시다. 최종 숫자는 실제 판정 요약 CSV에서 온다.

### 실제 D02에서 확인한 범위와 남은 과제

API 없이 수정 전·후를 각각 다시 읽었다. PDF에서는9노드/8연결을 추출하지만 기존 선택은 CSV10노드/9연결이다.
출처 정보를 제외한 전체 그래프 JSON·숫자·추출 연결선은 전후 같았다. 물리3쪽 공정도 전체를 Poppler로 렌더해
양쪽 세포주 분기, 중간체 합류, 나노파티클→최종원액→완제 연결을 직접 대조했다.

이 검사는 기존 선택 방식의 타당성 전체를 승인한 것이 아니다. `문서공통` 같은 판정 표시용 노드를 실제 제조단계와
분리하고, 실제 PDF 연결을 유지하면서 모든 판정 숫자를 잃지 않는 표시 구조는 별도 설계/회귀가 필요하다.
여러 공정도/페이지를 합치는 규칙, 복잡한 순환·재작업·동명 노드, 추출기 내부에서 이미 누락된 연결선의 검출도 미완료다.
새 출처 값은 추출 경로를 뜻할 뿐 원문 의미의 완전한 검증을 뜻하지 않는다.

재현: `pytest tests/test_flowchart_provenance.py`와 `.local_validation/probe_flow_v96.py`의 보존된 전후 결과.
정상 원본/기존 판정 결과는 변경하지 않았으며 최종 시험·브라우저·감사 상태는 `WORK_STATUS.md`를 따른다.
최종 전체1,472통과/skip0. 별도 `probe_flow_corpus_v96.py`는 D00~D12 원본13개를 모두 새로 읽어9노드/8연결씩 추출했다.
이는 형식/추출 회귀이며13개 모든 연결선의 새 육안 검증이나 새 시험 판정이 아니다. 종료 후 라이브러리의 임시파일 정리
잠금 경고가1회 있었고, 프로세스 종료 뒤 생성된 임시페이지PDF12개만 안전하게 정리했다. 추출 보고서와 원본은 보존했다.
