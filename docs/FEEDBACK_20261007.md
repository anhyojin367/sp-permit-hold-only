# 2026-10-07 추가 검토 의견 — 근거 펼침 표시

## 확인한 문제와 원인

사용자가 제공한 `더미데이터 검토 결과.docx`의 본문과 내장 캡처 21개를 확인했습니다. R07 제목·근거 캡처 2개와 시험별 근거 캡처 19개입니다. Word 렌더러는 로컬 LibreOffice가 없어 실행하지 못했으므로 본문 XML 및 내장 이미지 전체를 직접 검토하고 연결된 더미 허가서 PDF와 대조했습니다.

| 문제 | 원인 | 수정 |
|---|---|---|
| R07 허가서 근거에 문서확인번호가 표시됨 | MD 근거 HTML은 기존 표시 정리 함수를 거치지 않았음 | `_policy_evidence_links`의 허가서 인용문에 동일한 표시 정리 적용 |
| 시험별 펼침에 문서확인번호·`19/60`, `55/60` 등 페이지 장식이 다시 표시됨 | v109는 기본 설명을 정리했지만 펼침은 가공 전 추출문을 그대로 출력함 | 펼침에도 정리된 근거 문장 사용 |
| PCR·HAP·MAP·완제 항원함량 등 근거가 짧은 줄로 길게 늘어남 | 가공 전 PDF 줄바꿈을 펼침의 `pre` 요소에서 그대로 보존함 | PDF에서 잘린 문장 줄바꿈은 연결하고 실제 구조화된 행은 보존 |

문서확인번호는 허가서의 머리말·꼬리말이며 시험기준 수치가 아닙니다. 이번 제보는 확인한 출력 경로의 문제로, 새 판정 오류를 재현한 것으로 간주하거나 정상 판정 기준을 변경하지 않았습니다. 캡처 제목과 실제 시험명이 다른 경우에는 캡처 속 실제 시험을 기준으로 대응했습니다.

## 코드 변경과 보존 범위

- `sp_pdf_judger/ui_html.py`: 시험별 펼침을 **허가서 근거 문장 보기**로 변경했습니다. 정리된 문장임을 안내하며 원래 서식은 연결된 PDF에서 확인하도록 구분합니다.
- `sp_judgement_bridge.py`: MD 근거 중 허가서 인용문만 `permit_text_view`로 정리합니다. SP의 시험결과 표·비율·문서번호 같은 본문은 해당 정리 대상으로 삼지 않습니다. 링크의 PDF 파일과 쪽 번호는 바꾸지 않습니다.
- `sp_app.py`: 표시 캐시 버전만 `sp-ui-cache-v112-readable-evidence`로 올렸습니다. 판정 캐시 버전은 그대로입니다.
- `tests/test_feedback_20261007.py`: 캡처의 19개 시험 근거 및 R07 근거를 실제 PDF 추출 구간과 연결했습니다. 숫자·단위·본문 문자 보존, 원본 평가/메타데이터 불변, PDF 링크, HTML 이스케이프와 구조화 행을 검증합니다.
- `scripts/verify_text_presentation.py`: 저장 D00~D16 결과에서 펼침까지 검사하며 D00의 MD 근거 미리보기도 생성합니다.

원본 PDF/Word, 저장 평가의 기준·이유·근거, MD 로직, 상태 집계, CLOVA 통신 설정은 수정하지 않았습니다. 기존 `permit_text_view.py`의 보수적인 표시 처리도 바꾸지 않았습니다. 숫자를 무조건 지우거나 `106`을 일괄 `10⁶`으로 바꾸지 않습니다. 새 결과를 만들지 않고 기존 검수 영수증을 유지합니다.
