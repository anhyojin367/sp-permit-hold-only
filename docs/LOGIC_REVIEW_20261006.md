## R24가 깨진 원인

기존 `.structural-card-body div` CSS가 카드의 모든 하위 `div`에 `92px + 나머지 너비`의 2열 배치를 적용했다. 긴 이유를 위한 미리보기와 펼친 전체 이유 역시 `div`여서, 문장 텍스트가 첫 번째 92px 열에 갇혔다. 줄바꿈 추출이나 날짜 연산 오류가 아니라 **상위 카드 CSS가 하위 설명까지 침범한 문제**다.

수정 사항:

- 기준/이유의 제목·값 행만 `.structural-card-body > .structural-field`로 2열 배치한다.
- 값 영역은 블록 요소로 만들고 `min-width:0`을 적용한다. 내부 미리보기·전체 설명·근거 인용은 정상적인 문단 흐름을 유지한다.
- 좁은 화면의 1열 규칙도 직접 행에만 적용한다.
- 규칙 ID, 상태, 전체 설명, 근거 링크, 단위 대응 주석을 보존한다. 글을 짧게 삭제해 오류를 감추지 않는다.
- 구조·수치·시간 순서의 모든 규칙 카드에 공통 적용한다. R24 전용 하드코딩이 아니다.

기본 1265px 브라우저에서 D07의 미리보기 영역은 수정 전 내부 92px 열/높이 약739px에서 수정 후 정상 블록/전체452px/높이158px로 바뀌었다. D08도 정상 블록452px로 표시됐다. 이는 같은 저장 결과·같은 화면 크기에서의 비교이며 판정은 변하지 않았다.

## 규칙 적용 후에도 허가서 표기가 유지되도록 보완

D06·D09처럼 MD 규칙이 시험 결과를 불충족으로 확정하면 평가 객체의 출처가 `permit_pdf…`에서 `md_policy_guard`로 바뀐다. 기준 원문은 그대로 남지만, 출처 접두사만 보는 표시 코드는 허가서 위첨자 복원을 건너뛸 수 있었다.

- MD 불충족 사유와 SP 결과는 그대로 둔다. 과거 충족 이유를 다시 보여 주지 않으며, `106` 같은 SP 결과를 지수로 바꾸지 않는다.
- 원본 PDF의 SHA·위첨자 글꼴 확인 조건, 원문 펼치기, 다중 허가서의 모호한 서체 복원 방지는 그대로 유지한다.
- D06의 자릿수·CFU/PFU 오류, D09의 생존율 기준 불일치를 실제 저장 결과 카드로 재생해 불충족 이유와 `10⁶` 표시가 함께 유지됨을 브라우저에서 확인했다.

## 공개 확인 중 추가 보완: 최종 화면의 대기 표시 (v110)

공개 앱의 기존 D07은 문서함에서 완료로 표시됐지만, 상세 결과를 열면 준비 문구가 오래 유지됐다. 문서함의 요약 CSV와 전체 판정 캐시는 별도이므로 완료 요약만으로 전체 캐시 적중을 단정할 수 없다. 서버 내부 캐시 상태나 지연 원인은 관리자 로그 없이 확정하지 않았다.

확인 가능한 코드 문제는 최종 화면이 `future.result()`에서 동기 대기하여 진행 단계가 표시되지 않는다는 점이다. 이를 다음과 같이 수정했다.

- 화면에서만 `_defer_pending=True`를 사용한다. 진행 중이면 기존 작업 핸들을 가진 `JudgementPending`을 반환 경로로 전달하고 즉시 화면 실행을 돌려준다.
- 1초 간격의 Streamlit fragment에서 실제 작업 메시지와 경과 시간을 표시하고, 완료되면 전체 화면을 다시 그린다.
- 첫 화면 복귀 버튼은 판정 대기 전에 처리한다. 목록으로 돌아가도 작업을 취소하거나 같은 문서의 작업을 새로 만들지 않는다.
- 기존 동기 호출/백그라운드 처리/파일 잠금/캐시 식별/실패 시 재시도 정책은 그대로 둔다. 완료된 작업의 예외도 정상 오류로 표시한다.
- 화면 버전은 `sp-ui-cache-v110-final-review-progress`. 이 변경은 서버 연산이나 CLOVA 응답 시간을 줄였다는 의미가 아니다.

v110 최종 변경에 대한 추가 검증: **140 passed**, 실패 0, 3.78초. 실제 Streamlit AppTest의 미완료 작업 표시·목록 복귀, 동일 Future 재사용·완료 결과 캐시·실패 전달, 기존 재시도/실패 보호 및 v109 텍스트·레이아웃 회귀를 포함한다. v109 전체1786시험과 중복된 시험이므로 숫자를 합산하지 않는다. 기록: `.local_validation/logic_20261006/final_progress.xml`.

프로세스 간 파일 잠금까지 포함한 후속 **56 passed**, 실패 0, 40.73초도 확인했다(`final_locks.xml`). 이 수치 역시 중복 합산하지 않는다.
