# v92 실행 관리자 정리

## 바꾼 것과 바꾸지 않은 것

`sp_pdf_judger/pipeline.py`는 2,615줄에서 852줄로 줄었다. 현재 실행 클래스에서 호출되지 않는
옛 검사 함수·자료형41개와 이에만 필요한 상수/import를 제거했다. 다른 파일로 그대로 옮겨
파일 수만 늘리는 정리가 아니다. 제거 대상은 원본 Git 커밋 `db045c5`의 정의와 AST가 모두 같다.

사용 중인24개 정의의 AST는 변경 전과 동일하다. 여기에는 `DocumentJudgePipeline` 클래스 전체,
일반시험법 판정, 결과 집계, 제조요약도 페이지 선택/렌더 보조 함수가 포함된다. 공개 실행 진입점과
기존 시험에서 직접 가져오는 일반시험법 함수의 import 경로도 유지했다.

일반시험법을 전부 MD로 옮긴 것은 아니다. 그 판정은 여전히 코드에 남고,
문서 전체의 MD 정합성 검사는 기존처럼 `policy_engine.py`와 `policy_summary.py`를 통한다.
새 규칙·기준값·CLOVA 질문·화면 배치·허가서 의미 실험의 활성화는 이번 변경에 없다.

## 현재 파일을 읽는 순서

1. `DocumentJudgePipeline.__init__`: RAG, 허가서, CLOVA, 시험 판정기 준비.
2. `_activate_detail_profile`: 회사·제품의 기존 참고 문맥 연결.
3. `run`: MD 설정 확인 → 추출 → 시험별 판정 → MD 검사 → 근거·요약 구성.
4. 위쪽 보조 함수: 실제로 사용 중인 일반시험법과 페이지/집계 처리.

전에 섞여 있던 독립 제조요약도 날짜 판정·옛 페이지 연속성·소수점·서명 검사 구현은
현재 실행 경로가 아니므로 더 이상 이 파일에 남겨 두지 않는다. 현재 기능은 실행 중인 MD 규칙과
해당 연산을 봐야 한다. 삭제한 옛 함수가 예전 감사표에 적혀 있다는 이유로 활성 기능으로 세지 않는다.

## 과거 감사표와 현재 요구사항

`sp_pdf_judger/validation_audit_catalog.json`은 2026-09-06의29개 항목에 대한 과거 기록이다.
그 ID와 개수는 사용자가 이번에 제시한 A/B/C 목록과 다르다. 원래29행과 상태·설명을 유지하고
`scope: historical_snapshot`, 코드 기준 커밋, 현재 범위 문서 위치를 명시했다.
이 파일의 과거 구현 개수를 현재 완료율로 사용하면 안 된다. 현재 범위는 `VALIDATION_SCOPE.md`를 따른다.
