# 허가 원문 의미 분류 초안

이 도구는 허가서의 모든 추출 구간을 CLOVA에 나누어 보내 **검토할 후보**를 만든다.
실제 SP 합격/불합격 판정기나 필수시험 의무 승인기가 아니다. 기존 앱/UI/운영 MD에서 호출하지 않는다.
전체 응답이 도착해도 `semantic_correctness_verified: false`, `unreviewed`,
`runtime_activation: false`를 유지한다.

## 왜 별도 단계인가

허가서에는 시험 제목, 적합 기준, 시험 절차, 보관 조건, 변경 이력, 별첨 참조가 섞여 있다.
예를 들어 `희석 없이 분석`은 희석 절차의 조건이지 시험 자체를 생략해도 된다는 뜻이 아니다.
모든 원문에 답한 모델도 범주를 잘못 붙일 수 있으므로, 응답 완비와 의미 정확성을 분리한다.
이 초안만으로 기존 보류를 합격시키거나 새로운 필수/면제 MD를 활성화하지 않는다.

## 입력과 출력

- 입력: 단일 허가 PDF와 전체 단계 경로. 지금은 텍스트 추출 가능한 제공 허가서 범위다.
- 검색 상위 몇 건만 보내지 않는다. 전체 원문 소유 목록의 상위/선택/다른 단계/독립 안내를 전부 보존한다.
- 계획: 원문 지문, 전체 검토 목록, 모델/주소/토큰·묶음 제한, 프롬프트/응답 계약/구현 지문을 고정한다.
- 기본 묶음: 최대8구간/본문6000문자. 긴 단일 구간은 자르지 않고 중단한다. 문자 수는 토큰 수가 아니다.
- 모델의 응답: 구간/문단의 짧은 별칭, 복수 범주, 설명만 허용한다. 원문 인용·쪽·위치는 코드가 복원한다.
- 범주: 시험 의무 후보, 적합 기준, 절차, 공통조건 후보, 외부 참조, 기타, 불명확.
- 출력: `plan.json`, 실제 호출 시 `draft.json`/`draft.md`. 이전 출력 폴더는 덮어쓰지 않는다.

원문 인용은 PDF 문자 추출을 정규화한 구간이다. 문자 위치는 그 페이지 정규화 텍스트 내 위치이며,
PDF 바이트 위치나 화면 강조 좌표가 아니다. `model_note`는 원문 인용이 아니다.
초안 MD에 들어가는 모델 설명/원문은 HTML 및 Markdown 링크로 실행되지 않도록 이스케이프한다.

## 오류 처리

묶음마다 개수와 허용 ID를 제한하는 응답 스키마를 사용하고, 별도로 누락/중복/다른 소유 문단 연결을 검사한다.
요청 전후에는 원문과 계획을 다시 대조한다. 다른 파일, 설정·코드 변경, 누락된 구간, 잘못된 응답은 거부한다.
요청 실패 또는 계약 불일치가 생기면 다음 묶음을 호출하지 않는다. 이미 수락한 구간과 실패 응답은 미완성 감사 자료다.
제공자 예외의 상세 메시지는 키/헤더 노출을 막기 위해 결과에 적지 않는다.

분류기 자체는 오류 응답을 자동 재요청하지 않는다. 기존 CLOVA 클라이언트는 HTTP429에 제한된 대기를 재시도한다.
현재 결과 파일은 실행 종료 시 기록하며, 강제 종료 중간에는 계획과 이미 저장된 제공자 응답 캐시만 남을 수 있다.
중간 재개 기능은 없다. 응답 캐시는 동일 요청/스키마/엔드포인트/운영 규칙에만 재사용된다.

## 실행

기본 명령은 API를 호출하지 않고 계획만 만든다. 경로/출력 폴더는 실제 값으로 지정한다.

```powershell
.\.venv\Scripts\python.exe scripts/permit_obligation_draft.py `
  --permit '더미데이터/260922[더미허가문서]스카이코비원멀티주.pdf' `
  --stage-title '제조방법 및 시험기준' `
  --stage-title 'Component A 중간체 원액' `
  --stage-title 'Component A 중간체 원액에 대한 시험' `
  --output-dir .local_validation/permit_draft_new
```

새 출력 폴더와 `--live`를 지정해야 실제 CLOVA 전송/비용이 발생한다. 키는 기존 로컬 설정을 사용한다.
시험용 더미가 아닌 문서를 외부 전송할 때는 별도 데이터 사용 권한을 먼저 확인해야 한다.
자동시험은 다음과 같이 실행한다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_permit_obligation_draft.py tests/test_permit_review_packet.py -q
```

## 검증 한계와 다음 연결

v86 실제 제공 허가서는35묶음/276구간/147문단/23쪽의 응답·원문 대응 검사를 통과했다.
하지만 표지·약전 참조·절차와 적합 기준이 혼합된10구간을 따로 검토하면, 필요한 복수 범주를
모두 붙인 사례는0개였다. 이 표본은 취약 유형을 의도적으로 고른 것이며 전체 정확도0%라는 뜻은 아니다.
단일 대표 범주만 선택하는 경향이 있어, 이 방식의 의미 분류를 운영 의무 승인에 사용할 수 없다.
실패 원본 응답은 그대로 보존한다. 범주별 독립 응답/원문 근거 방식은 별도 소규모 실험이며 도구에 아직 반영하지 않았다.
후속 실험 두 번도 각각 첫 응답에서 형식 검증에 실패했다. 두 번째는 근거를 빈 문자열로 내거나
원문 밖의 따옴표를 더했고 표지의 복합 의미도 놓쳤다. 이를 자동 수정하여 수락하지 않았다.
15구간을 계획했지만 첫 묶음부터 거부했으므로 15구간 전체의 의미 정확도를 평가한 결과가 아니다.
후속 v87에서는 의미를 각각 독립 질문하고 근거를 원문 줄 ID로 선택하게 하는 별도 모듈을 검증했다.
MD만 수정한15구간 재시험 및 남은 한계는 `PERMIT_FACET_REVIEW.md`를 따른다. 이 v86 도구를 자동 승인 경로로 바꾸지는 않았다.

계획/응답의 전체 원문 대응은 코드로 검사할 수 있지만 모든 자연어 의미의 정확성은 그 검사로 보장되지 않는다.
현재 제공 파일에서 보이지 않는 별첨, 개정 적용 범위, 시험 의무 조건의 의미 검토는 남는다.
새 초안을 곧바로 운영 MD로 변환하거나, `other`/`procedure`라는 이유만으로 시험 면제를 만들지 않는다.
원문에 근거한 의무·조건 검토 후 기존 검토형 MD 계약과 독립 SP 사실 연결/오류 PDF 시험을 거쳐야 한다.
실행별 성공·실패와 검증 범위는 `WORK_STATUS.md`를 따른다.
