# 스카이코비원멀티주 허가서 우선 판정 설계

## 목적

SK바이오사이언스의 스카이코비원멀티주 SP를 판정할 때 등록된 품목 허가서를 최우선 기준으로 사용한다. SP와 허가서의 목차 번호는 서로 달라도 되며, 제조단계와 시험명의 의미가 같은 시험을 LLM이 연결한 뒤 허가서의 전체 조건과 SP 결과를 비교한다. 다른 회사와 제품의 기존 판정 순서와 결과는 변경하지 않는다.

## 적용 범위

- 회사가 `SK바이오사이언스`, `에스케이바이오사이언스`, `SK bioscience` 중 하나로 정규화되고 제품이 `스카이코비원멀티주`, `스카이코비원`, `SKYCovione` 중 하나로 정규화된 경우에만 허가서 우선 정책을 활성화한다.
- 이번에 제공된 `[더미허가문서]스카이코비원멀티주.pdf`를 프로젝트의 품목 허가서 카탈로그에 등록한다.
- 명시적으로 연결된 다른 품목의 허가서는 기존처럼 보류 항목을 보조 판정하는 용도로만 사용한다.
- 회사가 동국바이오사이언스인 문서를 제조번호로 스카이코비원멀티주에 매핑하는 기존 예외는 유지하되, 회사까지 SK바이오사이언스로 확인되지 않으면 이번 허가서 우선 정책은 적용하지 않는다.

## 핵심 정책

1. 허가서 목차 번호는 시험 동일성 판단의 근거로 사용하지 않는다. `2.1.2.1.10.3. 유정란접종시험`과 번호가 없거나 다른 번호를 가진 SP의 `유정란접종시험`은 번호를 제거한 시험명과 제조단계 문맥으로 연결한다.
2. 같은 이름의 시험이 여러 단계에 존재할 수 있으므로 시험명만으로 결정하지 않는다. `Component B 중간체 원액 > 확인시험`은 허가서의 `Component B 중간체 원액에 대한 시험 > 확인시험` 후보를 우선 제공한다.
3. 허가서의 해당 시험 문단은 다음 시험 제목 직전까지 전부 보존한다. 페이지가 바뀌어도 한 시험의 문단을 이어 붙여 기간, 온도, 검체 수, 계대, 생존률, 반응 유무 등 모든 조건을 LLM에 전달한다.
4. LLM이 `매핑됨`으로 응답한 시험은 허가서 판정이 기존 SP 자체 기준 판정을 덮어쓴다. 하나의 허가 조건이라도 명확히 만족하지 못하면 검수불합격이다.
5. LLM이 `없음`으로 응답하면 해당 시험에는 기존 SP 판정을 유지한다. `불명확`이면 허가서가 있는 품목에서 근거를 추측하지 않고 검수보류한다.
6. 허가서 기준 시험의 최종 합격·불합격은 반드시 LLM 응답으로 확정한다. LLM 호출 실패, 429, 파싱 실패 시 기존 SP 판정을 합격으로 확정하지 않고 검수보류하며 호출 실패 사실을 사용자용 판정 이유에 노출하지 않는다.
7. 검수불합격 이유에는 LLM이 선택한 실제 허가 조건과 충돌한 SP 결과를 포함한다. 출력 형식은 `허가서에는 '<조건>' 기준이 있으나 SP 결과 '<결과>'가 이를 만족하지 않아 검수불합격으로 판단했습니다.`로 정규화한다.

## 허가서 등록과 캐시

- 신규 카탈로그 파일 `sp_pdf_judger/permits/catalog.json`은 정책 ID, 회사/제품 별칭, 상대 PDF 경로, SHA-256, `authoritative`, `ignore_section_numbers`, OCR 정책을 기록한다.
- 신규 모듈 `sp_pdf_judger/permit_catalog.py`는 명시적으로 연결된 허가서와 카탈로그 허가서를 중복 없이 합치고, 정확히 일치하는 회사·제품에 대한 정책을 반환한다.
- `sp_judgement_bridge.ensure_judgement_artifacts`가 캐시 키를 만들기 전에 카탈로그를 해석한다. 따라서 PDF 내용이나 정책이 바뀌면 허가서 해시와 카탈로그 지문이 캐시에 반영된다.
- UI와 결과 메타데이터에는 실제 적용된 허가서 경로가 남아 기존의 `허가서 PDF 적용됨` 표시를 유지한다.

## PDF 텍스트 복구

제공된 PDF는 렌더링은 정상이나 PyMuPDF와 pypdf의 한글 텍스트 추출 결과에 대체문자가 다수 포함된다. 이 상태의 문자열은 검색이나 LLM 근거로 사용하지 않는다.

- 신규 모듈 `sp_pdf_judger/permit_ocr.py`가 페이지별 원문 텍스트의 한글 비율, 대체문자 비율, 연속 깨짐 패턴을 검사한다.
- 정상 페이지는 네이티브 텍스트를 사용한다.
- 깨진 페이지는 PyMuPDF로 이미지를 만든 뒤 Windows에 설치된 `ko-KR` OCR 엔진으로 읽는다. `scripts/windows_ocr_images.ps1`은 고정된 이미지 디렉터리만 읽고 UTF-8 JSON을 표준 출력으로 반환한다.
- Windows OCR을 사용할 수 없을 때는 설치된 Tesseract `kor+eng`를 시도한다.
- 네이티브 텍스트와 OCR 모두 유효하지 않으면 저장소에 추출 오류를 기록하고, 허가서 우선 시험은 검수보류한다.
- PDF SHA-256을 키로 한 페이지 텍스트 캐시를 운영체제 임시 디렉터리에 저장해 같은 허가서를 매 판정마다 OCR하지 않는다.

## 문단 구조화와 검색

`PermitChunk`는 기존 필드를 유지하면서 `page_start`, `page_end`, `section_path_titles`, `normalized_test_name`, `normalized_stage_path`를 추가한다.

1. 페이지별 텍스트를 하나의 문서 흐름으로 결합한다.
2. 숫자 목차를 이용해 부모-자식 구조만 복원하고, 검색 점수와 동일성 판단에서는 숫자 값을 제거한다.
3. 각 시험 문단은 다음 동급 또는 상위 제목 직전까지 자른다. 페이지 첫머리의 전 페이지 문단 연속 내용도 이전 문단에 포함한다.
4. SP 레코드에서는 `section_title`, `section_path`, `test_name`, `raw_text`로 제조단계와 시험명 후보를 만든다.
5. 시험명 의미 토큰과 제조단계 토큰으로 후보를 정렬한다. `확인시험`처럼 일반적인 시험명은 제조단계 토큰이 일치하지 않으면 직접 후보로 확정하지 않는다.
6. 상위 후보에는 번호 없는 허가서 경로, 물리 페이지 범위, 문단 전체를 포함한다. 문자 수 제한으로 조건을 중간 절단하지 않는다.

## LLM 판정 계약

`JudgeResponse`에 다음 선택 필드를 추가한다.

- `permit_match_status`: `matched`, `not_found`, `ambiguous`
- `matched_permit_test`: 번호를 제거한 허가서 제조단계 및 시험명
- `permit_basis`: 판정에 실제 사용한 허가서 조건
- `failed_requirements`: 만족하지 못한 허가 조건 목록

허가서 우선 호출에는 SP 제조단계, SP 시험명·방법·기준·결과, 허가서 후보 문단을 명확히 분리해 전달한다. 프롬프트는 목차 번호를 비교하지 말 것, 같은 시험인지 먼저 판단할 것, 매핑된 경우 모든 조건을 검토할 것, 허가서가 SP 기준보다 우선함을 명시한다.

`matched` 응답만 허가서 결과로 채택한다. 불합격인데 `permit_basis`와 `failed_requirements`가 모두 비어 있으면 응답을 신뢰하지 않고 검수보류한다. 판정 이유는 코드에서 허가 조건과 SP 결과를 포함하도록 후처리해 포괄적인 `허가서 기준 불일치` 문구만 남지 않게 한다.

## 판정 흐름

1. 파이프라인이 회사·제품 프로필과 허가서 정책을 확정한다.
2. 기존 SP 규칙/LLM 판정을 그대로 계산해 비교 기준으로 보존한다.
3. 허가서 우선 정책이 활성화된 경우 모든 시험 레코드에 대해 허가서 후보를 찾는다.
4. 후보가 있으면 LLM이 시험 매핑과 허가서 기준 판정을 한 번에 수행한다.
5. `matched`이면 허가서 판정을 최종값으로 사용하고 source를 `permit_pdf_llm_authoritative`로 기록한다.
6. `not_found`이면 보존한 기존 SP 판정을 사용한다.
7. `ambiguous`, LLM 오류, 유효한 허가서 텍스트 부재이면 검수보류한다.
8. 비대상 회사·제품은 현재의 `HOLD일 때만 허가서 보조 판정` 흐름을 그대로 수행한다.

표 형식 시험은 각 결과 행에 같은 허가 문단을 적용하되, 문단 전체 조건이 표 전체에 걸쳐 판단되어야 하는 시험은 전체 표 문자열과 구조화 행을 함께 LLM에 전달한다. 행별 응답 중 하나라도 불합격이면 상위 시험도 불합격으로 집계한다.

## 오류와 안전장치

- 허가서 PDF의 SHA-256이 카탈로그와 다르면 자동 적용하지 않고 검수보류 메타데이터를 남긴다.
- 허가서 파일명이나 폴더 위치만으로 다른 품목에 자동 연결하지 않는다.
- LLM은 검색 후보에 없는 허가 조건을 만들어 낼 수 없으며, `permit_basis`는 제공된 후보 문단에 포함된 표현과 의미상 연결되어야 한다.
- 여러 후보가 같은 일반 시험명을 갖고 제조단계가 구분되지 않으면 `ambiguous`로 처리한다.
- 사용자 화면에는 API 키, 내부 예외, OCR 임시 경로를 표시하지 않는다.

## 테스트 전략

신규 `tests/test_sky_covione_authoritative_permit.py`와 기존 관련 테스트에 다음 회귀 사례를 추가한다.

- 숫자 목차가 다른 동일 시험이 시험명과 제조단계로 매핑된다.
- Component B 중간체 원액의 확인시험이 다른 단계의 확인시험과 섞이지 않는다.
- 페이지를 넘기는 허가 문단의 앞뒤 조건이 하나의 LLM 요청에 모두 포함된다.
- 유정란접종시험의 요막강·계대·혈구응집·난황낭 조건 전체가 LLM 요청에 포함된다.
- CHO 마스터 세포주의 돼지유래바이러스 시험에서 21일 미만 결과를 반환한 LLM 불합격이 기존 SP 합격을 덮어쓴다.
- 불합격 이유에 실제 허가 조건과 불일치 결과가 포함된다.
- LLM 429/무응답, OCR 실패, 매핑 불명확은 검수보류가 된다.
- 허가서에 대응 시험이 없으면 기존 SP 판정을 유지한다.
- 같은 레코드를 다른 회사 또는 다른 제품으로 실행하면 기존 판정과 호출 순서가 유지된다.
- 기존 제품 매핑, 버전 표시/진행, 제조정보, 표 판정 테스트 전체가 통과한다.

테스트는 네트워크를 호출하지 않는다. 구조화된 가짜 허가서 문단과 응답 캡처형 LLM을 사용해 RED-GREEN을 확인하고, 제공 PDF의 존재·해시·텍스트 복구는 Windows 전용 통합 테스트로 별도 검증한다.

## 완료 기준

- 제공 허가서가 SK바이오사이언스·스카이코비원멀티주의 기본 허가서로 자동 연결된다.
- `2.1.x` 번호가 달라도 제조단계와 시험명이 같은 시험을 매핑한다.
- 허가서 문단의 모든 조건이 LLM 입력에 보존된다.
- 허가서와 충돌하는 SP 결과가 허가 근거를 명시한 검수불합격으로 표시된다.
- 비대상 회사·제품의 결과가 기존 회귀 테스트와 동일하다.
- 신규 테스트와 전체 테스트가 모두 통과한다.
