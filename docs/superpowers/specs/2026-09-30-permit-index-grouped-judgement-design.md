# 허가서 영구 인덱스 및 그룹 단위 결정론 판정 설계

## 목적

허가서 PDF를 같은 SP 판정 때마다 다시 추출·OCR·구조화하고 시험마다 CLOVA를 호출하는 비용을 없앤다. 허가서는 내용이 바뀌지 않는 동안 한 번만 추출·OCR·구조화하여 영구 인덱스로 재사용하고, SP는 같은 제조단계·시험·배치의 근거를 안전하게 묶는다. 수치·기간·단위와 명확한 정성 조건은 코드가 판정하고, 코드만으로 시험 매핑이나 조건 의미를 확정할 수 있는 경우에는 CLOVA를 호출하지 않는다.

이 설계는 `2026-09-16-sky-covione-authoritative-permit-design.md`의 회사·제품 범위, 허가서 우선성, 원문 근거 보존, 실패 시 보류 정책을 유지한다. 다만 다음 두 항목은 이 설계가 대체한다.

- 허가 시험마다 LLM 최종 판정을 필수로 하던 흐름을 `결정론 우선, 의미가 애매한 그룹만 LLM`으로 변경한다.
- `%TEMP%`에 페이지 텍스트만 저장하던 OCR 캐시를 영구 구조화 인덱스로 확장한다.

## 적용 범위

- 영구 인덱스 기반 추출·OCR·구조화 재사용 기능은 연결된 모든 허가서 PDF에서 사용할 수 있게 구현한다.
- 판정 결과를 바꾸는 결정론 우선·그룹 평가 모드는 허가 정책에 명시된 경우에만 활성화한다. 최초 활성 대상은 SK바이오사이언스의 스카이코비원멀티주다.
- 다른 회사·제품과 비권위 허가서의 기존 판정 순서와 결과는 그대로 유지한다.
- 기존 제품 매핑, 제출 버전 표시, 4.0 버전 안내 후 진행, 제조정보 및 회귀 로그 동작은 변경하지 않는다.
- 캐시에는 허가서 원문과 구조화 근거만 저장한다. SP 결과, API 키, CLOVA 응답, 사용자 계정 정보는 저장하지 않는다.

## 비목표

- 여러 PC가 공유하는 원격 캐시나 서버형 데이터베이스를 도입하지 않는다.
- 배치번호를 주변의 임의 영문·숫자 조합이나 파일명만 보고 추정하지 않는다.
- 허가서에 없는 시험을 새로 만들어 내거나 다른 제조단계의 같은 이름 시험을 빌려 판정하지 않는다.
- 모든 자연어 허가 조건을 정규식으로 강제 판정하지 않는다. 완전하게 해석하지 못한 조건은 LLM 대상 또는 보류로 남긴다.

## 기존 구현에서 재사용할 기반

- `permit_ocr.py`의 페이지별 네이티브 텍스트 품질 검사, 손상 페이지만 수행하는 OCR, SHA-256 기반 검증을 재사용한다.
- `PermitChunk`의 페이지 범위, 제조단계 경로, 정규화 시험명, 원문 위치 근거와 계층 정보를 그대로 보존한다.
- `PermitPdfStore.search()`의 제조단계·시험명 검색과 교차 단계 차단 정책을 재사용한다.
- `criteria_parser.py`, `unit_normalizer.py`, `judgement.py`, `numeric_safety.py`의 수치·범위·단위 비교기를 공통 조건 실행기로 확장한다.
- 프로세스 간 중복 생성을 막을 때 `sp_process_lock.artifact_process_lock()`을 재사용한다.
- 기존 전체 판정 산출물 캐시는 유지하되, 허가 인덱스는 SP별 최종 결과 캐시와 별도로 관리한다.

## 전체 데이터 흐름

### 최초 처리 또는 캐시 무효화

1. 허가서 해시를 기존 허가서 해석 단계에서 한 번 계산하고 이후 구성요소에 전달한다.
2. 영구 인덱스 키를 계산하고 동일 키 생성 잠금을 획득한다.
3. PDF의 네이티브 페이지 텍스트를 추출한다.
4. 네이티브 텍스트가 손상된 페이지만 렌더링하여 OCR한다.
5. 페이지 흐름을 제조단계·시험명·하위 조건·원문 위치 근거로 구조화한다.
6. 허가 문장에서 실행 가능한 조건과 코드로 해석할 수 없는 조건을 분리한다.
7. 페이지 텍스트, 구조화 문단, 조건, 검색 인덱스와 진단정보를 임시 파일에 기록한 뒤 원자적으로 게시한다.

### 이후 처리

1. 기존 허가서 해석 단계에서 얻은 해시와 정책·파서 버전으로 인덱스를 찾는다.
2. 인덱스 스키마, 해시, 정책 형태와 원문 위치 근거를 검증한다.
3. 유효하면 PDF 페이지 추출·OCR·문단 파싱을 호출하지 않고 구조화 객체를 복원한다.
4. 메모리에는 `(정규화 제조단계, 정규화 시험명)`별 문단 ID 목록과 시험명 역색인을 올린다.
5. 현재 SP의 그룹별 검색과 판정에 이 인덱스를 재사용한다.

따뜻한 경로에서도 허가서 변경 검증에 필요한 내용 해시는 보존한다. 다만 현재처럼 카탈로그 해석, OCR 모듈, 문단 저장소에서 같은 파일을 반복 해시하지 않고 최초 계산값을 전달한다.

## 영구 캐시 위치와 키

기본 루트는 Windows의 `%LOCALAPPDATA%\SPValidator\permit_index`다. 테스트·운영 환경에서는 `SP_PERMIT_INDEX_DIR` 환경변수로 변경할 수 있다. `%LOCALAPPDATA%`를 사용할 수 없는 환경은 사용자별 애플리케이션 캐시 경로를 사용하며, 저장소 내부나 `%TEMP%`를 기본값으로 사용하지 않는다.

캐시 키는 다음 값의 정렬된 JSON을 SHA-256으로 해시해 만든다.

- 허가서 PDF SHA-256
- OCR 스키마 버전
- OCR 모드, 언어(`kor+eng`), 렌더링 DPI와 OCR 구현 버전
- 허가 문단 파서 스키마 버전
- 조건 파서 스키마 버전
- 허가 정책 ID와 구조에 영향을 주는 정책 값

파일명, 절대경로, 수정시간만으로 캐시 동일성을 판단하지 않는다. 파일 내용이 같으면 위치가 달라도 같은 인덱스를 재사용하고, 내용 또는 파서 의미가 바뀌면 다른 키를 사용한다.

## 영구 인덱스 형식

인덱스는 사람이 감사할 수 있는 UTF-8 JSON으로 저장하고 신규 외부 데이터베이스 의존성을 추가하지 않는다. 한 항목은 다음 내용을 가진다.

- 스키마 및 생성기 버전
- PDF SHA-256, 페이지 수, 원본 표시명
- 페이지별 선택 텍스트, `native`/`windows_ocr`/`tesseract` 출처와 오류
- `PermitChunk` 전 필드와 `owned_spans`, 상위 문단 ID
- 정규화 제조단계, 정규화 시험명, 검색 별칭 적용 전 원래 식별자
- 허가 조건 목록과 각 조건의 원문 근거 ID
- `(stage_key, test_key) -> evidence_id[]` 검색 맵
- 생성시간, OCR·파싱 진단정보

검색 별칭과 MD 규칙은 편집 즉시 반영되어야 하므로 영구 인덱스에 확정 매핑으로 굳히지 않는다. 인덱스에는 원문 기반 정규화 결과만 저장하고 현재의 MD 별칭은 로드 후 검색 단계에 적용한다.

## 캐시 생성과 동시성

- 캐시 키마다 고정 잠금 파일을 두고 기존 OS 파일 잠금으로 단일 생성자만 추출·OCR·파싱한다.
- 잠금을 기다린 프로세스는 잠금 획득 후 캐시를 다시 읽고, 이미 완성되어 있으면 재생성하지 않는다.
- JSON은 같은 디렉터리의 고유 임시 파일에 완전히 기록하고 검증한 뒤 `os.replace()`로 게시한다.
- 스키마 불일치, 잘린 JSON, 해시·페이지·근거 ID 불일치는 캐시 미스로 취급하여 잠금 안에서 재생성한다.
- 재생성 실패 시 기존 손상 캐시를 신뢰하지 않으며 해당 허가 판정은 검수보류로 닫는다.
- 캐시는 자동 TTL로 삭제하지 않는다. PDF나 처리 버전이 바뀌면 새 키가 생기므로 이전 항목은 감사자료로 남긴다.

## 허가 조건 구조

허가 문단의 각 의무 문장은 원문을 보존하면서 가능한 경우 다음 내부 형태로 변환한다.

- 수치 비교: 최소, 최대, 초과, 미만, 정확히 일치
- 범위: 하한·상한 및 경계 포함 여부
- 기간: 일·시간·분과 최소·최대·정확 기간
- 온도 및 허용오차: 예를 들어 `36 ± 2 ℃`
- 개수·비율: 예를 들어 `최소 10개`, `80% 이상`
- 단위가 있는 측정값과 호환 가능한 단위 변환
- 명확한 정성 조건: 음성/양성, 검출/불검출, 있음/없음, 적합/부적합
- 복합 조건의 `AND` 관계와 단계·방법 범위

각 조건은 고유 ID, 조건 종류, 연산자, 정규화 값·단위, 적용 범위, 원문 인용, 페이지와 문단 ID를 가진다. 문단의 규범적 조건 중 하나라도 코드가 완전히 구조화하지 못하면 그 문단을 `부분 구조화`로 표시한다. 구조화되지 않은 조건을 버리거나 이미 구조화된 일부 조건만으로 합격시키지 않는다.

## SP 배치 근거와 그룹 키

SP의 배치번호는 다음과 같은 명시적 근거만 허용한다.

- 구조화 표의 `lot_no` 또는 명시적 배치 열
- 같은 시험 레코드나 같은 시험 절에 라벨과 함께 기재된 `제조번호`, `배치번호`, `로트번호`, `Lot No.`
- 추출기가 원문 위치와 함께 유일하게 연결한 상위 시험 절의 배치 필드

재료 로트, 대조군 로트, 허가서의 예시 번호, 파일명 속 문자열은 SP 시험 배치로 사용하지 않는다. 동일 범위에 서로 다른 배치값이 있으면 `conflict`, 명시값이 없으면 `missing`으로 기록한다.

그룹 키는 다음을 모두 포함한다.

- 정규화 제조단계
- 정규화 시험명
- 명시적 배치번호
- 서로 호환되는 시험방법·허가 후보 근거

제조단계나 배치번호가 없거나 충돌하면 다른 레코드와 묶지 않고 검수보류한다. 시험명과 배치가 같아도 제조단계 또는 시험방법이 충돌하면 별도 그룹으로 분리하고 근거가 부족한 그룹은 보류한다.

그룹은 UI 레코드를 없애는 병합이 아니다. 원본 레코드·행과 제출값은 그대로 유지하고, 같은 판정 입력을 공유하는 평가 단위만 만든다.

## 그룹 판정 순서

1. SP 그룹의 모든 원본 레코드와 표 행에서 결과 사실을 추출한다.
2. 제조단계·시험명으로 허가 인덱스를 조회한다.
3. 후보가 없으면 현재 허가 정책의 기존 `not_found` 처리를 유지한다.
4. 한 후보와 모든 허가 조건이 결정론적으로 매핑되면 코드가 비교한다.
5. 한 조건이라도 불충족이면 그룹은 검수불합격이다.
6. 모든 조건이 충족되고 누락·미해석 조건이 없을 때만 검수합격이다.
7. 결과 근거가 없거나 배치·단계가 불명확하면 CLOVA를 호출하지 않고 검수보류한다.
8. 시험 후보가 복수이거나 자연어 조건·SP 사실의 의미 연결만 애매하면 그룹당 CLOVA를 한 번 호출한다.
9. 그룹 결과는 각 원본 레코드에 동일한 그룹 ID와 공통 근거를 연결하되, 화면의 실제 기준·결과·페이지 정보는 유지한다.
10. 그룹 요약은 `불합격 > 보류 > 합격` 우선순위로 집계한다. 한 행의 합격을 다른 행의 충족 근거로 복사하지 않는다.

## CLOVA 호출 게이트

CLOVA 호출 전에 코드가 다음 셋 중 하나를 명시적으로 반환한다.

- `deterministic`: 후보와 모든 조건·결과 사실이 완전하게 연결되어 코드가 최종 판정한다.
- `ambiguous_llm`: 원문은 충분하지만 시험 후보 선택 또는 자연어 의미 연결이 복수로 가능하다.
- `hold_without_llm`: 배치·결과·원문 근거가 없거나 OCR·캐시가 손상되어 모델도 안전하게 판단할 수 없다.

`ambiguous_llm`만 CLOVA를 호출한다. 한 그룹은 최대 한 번 호출하고 결과를 그룹 내 동일 근거 레코드에 재사용한다. 요청에는 전체 허가 후보 문단, 조건 ID, SP 사실 ID, 제조단계와 배치 근거를 포함한다.

CLOVA 응답은 선택한 허가 문단 ID, 조건 ID와 SP 사실 ID를 반환해야 한다. 코드는 ID 존재 여부, 원문 인용, 단계·배치 범위와 조건 누락을 검증한다. 수치·기간·단위 조건은 CLOVA가 합격이라고 답해도 코드가 다시 계산하며, 결정론적 불합격을 모델 응답이 뒤집을 수 없다. 응답 누락, 중복 ID, 근거 불일치, 429, 시간초과, 파싱 실패는 검수보류다.

## 비대상 정책과 기존 동작 보존

- 허가 정책에 `evaluation_mode=deterministic_first`가 없으면 현재 레코드 단위 판정 흐름을 유지한다.
- 스카이코비원멀티주 카탈로그 정책에만 최초로 `evaluation_mode=deterministic_first`를 설정한다.
- 기존 `authoritative`, `ignore_section_numbers`, `require_llm` 필드는 호환성을 위해 유지한다. 결정론 우선 모드에서 `require_llm`은 애매한 그룹을 자동 합격시키지 말고 LLM 실패 시 보류하라는 의미로 사용한다.
- 캐시 인덱스 기능 자체는 판정 결과를 변경하지 않는다. 캐시에서 복원한 `PermitChunk`와 원문 근거는 캐시 없이 새로 생성한 결과와 정확히 같아야 한다.
- 기존 SP 자체 규칙과 일반 시험방법 규칙, 정책 검사와 UI 집계 순서는 유지한다.

## 오류 처리

- 허가 PDF 해시가 카탈로그와 다르면 인덱스를 만들거나 사용하지 않고 기존의 카탈로그 오류 보류 정책을 적용한다.
- OCR에서 읽을 수 없는 페이지가 허가 후보 범위에 포함되면 합격으로 확정하지 않는다.
- 캐시가 유효하지 않고 재생성도 실패하면 내부 예외를 화면에 노출하지 않고 검수보류 이유와 진단 메타데이터를 남긴다.
- 배치 누락·충돌, 제조단계 충돌, 복수 허가 후보, 부분 조건 구조화 상태를 서로 다른 사유 코드로 기록한다.
- 다른 배치나 다른 단계의 값을 대신 사용하지 않는다.
- CLOVA가 비활성화되어도 결정론적 판정은 정상 동작하고, `ambiguous_llm` 그룹만 보류한다.

## 관측성과 UI

화면의 기존 시험명, 제출 기준·결과, 페이지 및 허가서 적용 표시는 유지한다. 결과 메타데이터에는 다음 감사 항목을 추가한다.

- `permit_index_cache_hit`, `permit_index_key`, `permit_index_schema`
- 인덱스 로드 또는 생성 시간과 OCR 수행 페이지 수
- 전체 원본 시험 수와 그룹 수
- 결정론 판정, LLM 대상, 모델 없이 보류된 그룹 수
- 실제 CLOVA 호출 수와 캐시·그룹화로 절약된 예상 호출 수
- 그룹 ID, 배치 근거 종류와 판정 경로

메타데이터에는 API 키, 전체 로컬 사용자 경로 또는 모델 내부 오류 전문을 넣지 않는다.

## 캐시 및 최종 산출물 무효화

- 허가 인덱스 스키마와 조건 파서 버전을 최종 판정 산출물 키에 포함한다.
- 판정 흐름이 달라지므로 `JUDGEMENT_CACHE_VERSION`을 올려 과거 pickle 결과가 새 코드의 결과처럼 재사용되지 않게 한다.
- MD 검색 별칭이나 정책 규칙 변경은 기존 규칙 지문으로 최종 결과를 무효화한다. 원문 구조가 변하지 않았다면 허가 인덱스 자체는 재사용한다.

## 테스트 전략

모든 구현은 네트워크 없는 TDD로 진행한다.

### 영구 인덱스

- 첫 인스턴스는 추출·OCR·구조화를 한 번 수행하고 두 번째 새 인스턴스는 어느 작업도 다시 호출하지 않는다.
- PDF 내용, OCR 모드·언어·DPI, OCR/문단/조건 파서 버전 또는 구조 영향 정책이 바뀌면 캐시가 무효화된다.
- 잘린 JSON, 잘못된 해시·페이지 수·근거 ID는 사용하지 않고 재생성한다.
- 동시에 같은 키를 요청해도 추출·OCR·파싱은 한 번만 실행된다.
- 캐시에서 복원한 페이지, 문단, 조건과 원문 위치 근거는 최초 생성 객체와 같다.
- 제공된 스카이코비원멀티주 허가서의 두 번째 처리에서는 OCR·문단 파서 호출 수가 0이다.

### 배치 그룹

- 같은 단계·시험·배치는 한 그룹이 되고 서로 다른 배치는 분리된다.
- 같은 시험명이라도 제조단계가 다르면 분리된다.
- 배치 누락·복수·재료 로트 오인 가능성은 그룹화하지 않고 보류한다.
- 그룹 안의 한 결과가 불합격이면 전체 그룹 요약은 불합격이지만 각 원본 행은 그대로 남는다.
- 한 레코드의 합격 결과가 다른 레코드의 누락 결과를 채우지 않는다.

### 코드 판정과 호출 수

- 수치 최소·최대·범위·경계값, 기간, 온도 허용오차, 최소 개수, 생존률, 호환 단위와 단위 불일치를 검증한다.
- 유정란접종시험의 `10~11일`, `최소 10개`, `36 ± 2 ℃`, `3일`, `80% 이상`, 계대 및 혈구응집 조건이 모두 충족되어야 한다.
- 명확한 조건 그룹은 CLOVA 호출 0회다.
- 같은 애매한 시험·배치 그룹은 레코드 수와 무관하게 CLOVA 호출 1회다.
- 배치·결과 근거 부족, OCR 실패, 손상 캐시는 CLOVA 호출 0회와 검수보류다.
- 모델의 잘못된 합격 응답이 코드의 수치·기간·단위 불합격을 뒤집지 못한다.

### 회귀와 성능

- 비대상 회사·제품은 변경 전과 최종 상태·이유·호출 순서가 같다.
- 기존 제품 매핑, 버전 표시와 진행, 제조정보, 허가 우선 판정, 필수시험, 날짜·소수점·회귀 로그 테스트를 모두 실행한다.
- 벽시계 시간의 불안정한 CI 임계값 대신 따뜻한 경로에서 PDF 페이지 추출·OCR·문단 파서가 0회인지 검증한다.
- 로컬 통합 벤치마크는 최초/재처리 시간, 허가서 페이지 수, OCR 페이지 수와 CLOVA 호출 감소량을 보고한다.

## 완료 기준

- 동일 허가서는 최초 처리 후 앱 재시작 뒤에도 PDF 페이지 추출·OCR·문단 파싱 없이 구조화 인덱스를 재사용한다.
- 같은 제조단계·시험·배치만 함께 평가되고 누락·충돌 배치는 보류한다.
- 코드가 완전히 해석할 수 있는 수치·기간·단위 및 명확한 정성 조건은 CLOVA를 호출하지 않는다.
- 애매한 시험은 그룹당 최대 한 번만 CLOVA를 호출하며 모든 응답 근거가 원문 ID로 검증된다.
- 캐시·OCR·모델 오류가 합격으로 조용히 전환되지 않는다.
- 실제 제출값과 기존 UI 표시는 유지된다.
- 비대상 회사·제품 회귀가 변하지 않고 신규 테스트와 전체 테스트가 통과한다.
