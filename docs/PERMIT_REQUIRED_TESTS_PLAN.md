## 연산 계약

1. MD에는 적용 제품, SP 제조단계 선택 조건, 연결할 허가 단계 경로, 필요 시 명칭 동등성 정책을 둔다. 기준값/필수시험 이름을 Python에 제품별로 하드코딩하지 않는다.
2. 선택한 허가 단계의 전체 하위 문단을 열거한다. SP에 이미 존재하는 시험을 쿼리해 검색한 상위 몇 개만 검사하면 누락 시험을 찾을 수 없다.
3. 문단 ID는 문서 지문 + 전체 제목 경로 + 실제 페이지 + 문단 위치로 구분한다. 같은 이름의 다른 제품/단계/개정 허가서는 합치지 않는다.
4. LLM이 조건부 수행 여부나 명칭 대응을 판단할 때도 원문 문단 ID/문장 근거를 전부 반환해야 한다. 검색 별칭은 후보 확장일 뿐 의미 동등성 확정이 아니다.
5. 조건부 요구사항의 적용 대상·시험 차수·용기 규격을 확인하지 못하면 보류한다. 조건을 무조건 필수 또는 제외로 바꾸지 않는다.
6. 배치별 수행근거를 분리한다. 한 배치의 무균시험으로 다른 배치의 무균시험 누락을 채우지 않는다. 배치 연결이 모호하면 보류한다.
7. 허가서 없음/추출 실패/단계 다중 매칭은 보류한다. 연결된 다른 단계나 자사 기준으로 필수 목록을 임의 대체하지 않는다.
8. 요구사항이 확정되고 SP 추출 범위가 확인된 경우에만 누락을 불충족으로 판단한다. 일부 불충족과 다른 항목의 불완전 근거는 동시에 감사 기록에 남긴다.
9. 결과는 기존 MD Finding/원문 링크 경로에 연결한다. UI 레이아웃이나 요약 집계 체계를 새로 만들지 않는다.

`PERMIT_APPLICABILITY_PROTOCOL.md` 참조. 모델은 조건별 근거와 truth를 반환하며 코드가 독립 비교한 뒤
최종 수행 필요/미해당/불명을 계산한다. 실제 API에서 종합 판단 혼동을 관찰하여 이 역할을 분리했다.
이 기능은 합성 문서의 검토된 설정과 좁은 SP 양식만 검증하며, 운영27MD에는 연결하지 않았다.
원문 의미에 대한 설정 검토/실제 SP 표 어댑터/시험 존재 검사 연결은 다음 작업이다.

아래는 v77에서 정한 계약과 아직 남은 전체 범위다.

v77은 1번의 위치/계층 기반 원문 소유 범위만 구현했다. `PERMIT_SOURCE_OWNERSHIP.md` 참조.
별도 전체 근거 목록은 원문을 중복 소유하지 않으며 날짜/독립 안내도 남긴다. 이를 아직 필수 의무 목록으로
분류하지 않는다. 2~5번 중 검토된 수치 조건 계약만 v78이 다루며 일반 자연어 해석과 운영 연결은 남았다.

후속 구현의 입력 경계: v77 목록에 오류가 있으면 조건 해석으로 넘어가지 않는다. 정상 목록에서도
`unscoped_ids`(전역 안내/제품정보/날짜 이력)를 누락하면 전체 검토 완료로 수락하지 않는다.
날짜가 최신이라는 이유만으로 개정 우선순위를 추정하지 않는다. 먼저 작은 합성 문서의 검토된
의무/조건 ID 집합과 독립 SP 사실 집합으로 검증기를 만들고, 그 뒤 CLOVA 분류와 MD 연결을 붙인다.
조건 식 자체의 근거와 SP 값의 근거를 분리하고, 다른 배치·다른 단계 값 및 절차용 조건을
시험 수행 조건으로 인용한 응답은 거부한다. 숫자·단위 비교는 근거가 고정된 범용 연산으로 확인한다.

기존 `permit_llm_protocol.py`는 개별 시험의 검색 후보/문장 전체를 판정하는 계약이다.
이미 존재하는 SP 시험의 후보를 판정하므로, 빠진 시험을 찾기 위한 전체 필수목록으로 재사용하면 안 된다.
새 조건 계약은 다음 범위를 별도 실패 시험부터 구현한다.

1. 허가 파일/전체 제목 경로/문단 위치를 포함한 고정 근거ID로 상위 공통조건과 말단시험을 묶는다.
   의무 목록을 top-k로 자르지 않으며 별도 개정파일의 적용 관계가 미확정이면 보류한다.
2. LLM은 조건 해석과 대응 후보를 반환하되, 모든 의무ID를 정확히 한 번 포함하고 참조 조건ID와
   SP 사실ID를 돌려준다. 없는 ID·중복·누락·다른 단계/배치 참조·인용 불일치는 거부한다.
3. 시험 차수/용기규격/조건의 실제 입력값은 독립 원문 근거에서 읽는다. 필드가 없으면 조건 불명확이며
   LLM이 추측한 값이나 다른 배치의 값으로 필수/면제를 확정하지 않는다. 수치 조건은 검증된 연산으로 재계산한다.
4. `not_required`는 근거가 입증된 조건 불충족일 때만 허용한다. 단순 시험 부재/절차 분류/N/A를
   면제 사유로 쓰지 않는다. 상위 조건을 누락하거나 자식만 읽은 응답도 수락하지 않는다.
5. 작은 합성 허가/사실로 조건 충족·불충족·사실누락·상위조건 누락·상충·다중배치·ID변조·문서 내 명령문을
   시험한다. 이후 별도 합성 PDF 및 지정 CLOVA 실호출로 검증하고 운영27개 규칙은 활성화 전까지 보존한다.

이는 구현 계획이며 v75의 독립 구간 검증 결과에 포함되지 않는다.

v75 읽기 전용 사전 관찰: 제공 허가 파서의 상위 문단 `text`에는 하위 시험 본문까지 포함된다.
상위 text와 모든 자식 text를 그대로 연결하면 같은 문장을 여러 의무/공통조건으로 중복 사용할 수 있다.
원문 위치/계층에 따라 각 문장의 소유 범위를 구분하는 계약을 먼저 시험해야 하며, 단순 문자열 삭제로
중복을 없애거나 상위 문단 전체를 모든 자식에 적용해서는 안 된다.
키워드 후보13문단은 상위 중복을 포함하며 실제 조건부 의무13개가 아니다. 확인한 말단의 “경우”는
물리5쪽 유정란접종 방법,16쪽 나노파티클 SE-HPLC 희석,19~20쪽 완제 SE-HPLC 희석 등의 문맥이다.
특히 농도에 따른 희석 생략은 시험 자체의 면제 근거로 취급하지 않는다. 이 관찰은 문서 전체에서
조건부 의무가 전혀 없다는 결론이 아니며, 용기50/100mL·재시험 단계 등은 별도 합성 변형으로 검증해야 한다.

### 공통 회귀

- 작은 합성 레코드: 동일 시험명/다른 단계, 절 번호 재사용, 상·하위 시험, 서로 다른 레코드 조각, 2개 배치 중 1개 누락, 조건 미확정, 허가 중복/상충.
- 별도 합성 PDF: 정상/시험 누락/단계 누락/배치 누락/근거 불명확. 원본 더미는 수정하지 않는다.
- 제공 D00~D12: 기존 지정 오류 및 정상 오탐 회귀, 새 필수 목록의 원문 근거 검토, CLOVA 실제 판정과 누락/보류 감사.
- 마지막으로 기존 화면의 카드, 원문 링크, 집계 및 업로드 연결 회귀.

이 계약을 만족하는 범위부터 단계적으로 활성화한다. 147개 문단을 무작정 모두 필수시험으로 간주하거나 보류를 없애기 위해 규칙을 약화하지 않는다.
