# 실제 SP 표의 조건값 연결 (v81, 선택형)

`single_batch_scoped_records_v1`은 v80의 MD 수치 실행기에 붙는 새 입력 양식이다.
숫자 계산/LLM 응답 검증기를 다시 만들거나 기존 `explicit_page_block_v1` 의미를 바꾸지 않는다.
회사/제품·허가 전체ID·전체 의무·조건 검증은 그대로다. 운영27규칙이나 화면에는 아직 자동 적용하지 않는다.

## 왜 별도 연결이 필요한가

D00 물리13쪽에는 Component A/B 정보와 완제품 머리말 제조번호가 함께 있다.
페이지 전체에서 처음 보이는 `제조번호`나 `제조량`을 가져오면 다른 대상을 연결할 수 있다.
따라서 MD에서 아래 범위를 각각 검토해서 지정한다.

| MD 입력 | 역할 | 조건 |
|---|---|---|
| `source_scopes[].sp_stage` | 허가 의무와 대응하는 SP 제조단계 | 선언된 단계 전부와 정확히 대응 |
| `batch_source` | 독립 제조번호 정보 절 | content/info 레코드, 유일한 단일 배치 |
| `fields[].source` | 각 조건값이 적힌 정보/시험 절 | 정확한 전체 경로, 타입, 시작/끝 원문 경계 |
| 시험 절의 `test_name` | 어떤 시험의 사실인가 | 필수이며 해당 레코드 원문에도 있어야 함 |
| `fields[].label` | 실제 원문 필드명 | 완전한 줄 첫 항목명, 같은 줄 또는 인접 값 줄 |
| `fields[].name` | MD 조건의 논리 필드명 | 그 단계에 적용되는 모든 조건 필드와 일치 |

한 조건값의 이름과 실제 원문 항목명이 다를 수 있다. 예를 들어 합성 예제의 `농도`는
정확히 지정한 `농도확인시험`의 `시험결과`에서 읽는다. 아무 시험의 결과를 농도로 추측하지 않는다.
이 대응의 **의미를 검토하는 책임은 MD 작성자에게 있다**. 해시나 정확한 문자열 연결이 의미 검토를 대신하지 않는다.

전체 실행 예제는 `examples/scoped_condition_rules/conditions.md`다. 예제 지문은 아래 스크립트가
생성하는 합성 허가서 전용이다. 다른 허가서의 ID를 자동 복사해서 적용하면 안 된다.

## 실제 실행과 근거

`evaluate_numeric_pdf(rules_md, store, sp_pdf, records, company=..., product=...)`가 원본 PDF 바이트를
한 번 읽고 그 스냅샷에서 전체 페이지를 추출한다. 호출자가 일부 페이지/Target/모델 응답을 공급하는
인자는 없다. 레코드는 실제 추출기의 결과이며, 값의 권위가 아니라 원문 연결을 대조하는 입력이다.

1. MD 범위의 시작/끝 문구가 문서 전체에서 유일하고 순서가 맞는지 확인한다.
2. 해당 경로·타입·시험명의 레코드가 유일하고, 원문 전체와 기재 페이지가 범위 안에 있는지 확인한다.
3. 독립 정보 절 원문의 제조번호 전체와 추출 레코드를 대조한다. 한 배치만 허용하며, 여러 배치를
   하나로 합치거나 임의 기본 번호를 넣지 않는다.
4. 각 조건 필드의 원문 전체 개수/값을 해당 절 레코드와 대조한다. 다른 절에 있는 값은 쓰지 않는다.
5. 원문에서 조건 Fact를 만들고 v80 수치 계산기로 전달한다. 시험차수/절차 조건도 각 지정 범위만 사용한다.
6. 서로 다른 제조단계의 원문 범위가 겹치거나 조건 절에 다른 제조번호가 있으면 거부한다.

`source_pdf_sha256`, `source_page_count`, `source_scope_audit`, 배치/사실ID, 페이지·문자 위치,
인용문을 반환한다. 위치와 인용은 **NFKC 정규화된 페이지 텍스트 기준**이며 PDF 픽셀 좌표는 아니다.
값만 한 줄로 고쳐 인용을 바꾸지 않는다. 실행 중 PDF 또는 MD가 변경되면 결과 반환을 거부한다.

## 보류와 거부를 구분

- 자기 절에 필드가 없고 원문/추출 양쪽에 없으면 Fact가 없다. 수행 조건은 unknown으로 보류하며
  다른 Component의 같은 이름 필드를 가져오지 않는다.
- 실제 같은 절에 중복/충돌 값이 있으면 모두 Fact로 보존한다. 하나만 골라 적용/면제를 확정하지 않는다.
- 단위 불일치는 v80 비교기에서 unknown이다. 자동 단위 환산을 추가한 것이 아니다.
- 미추출 필드·레코드 위조·잘못된 페이지/경계·중복 레코드·배치 충돌·복수 배치는 `ValueError`로
  중단한다. 향후 운영 연결 시 검사 불가/보류로 다뤄야 하며 합격이나 빈 의무 목록으로 바꾸면 안 된다.
- 결과의 complete는 수행 여부 계산 완료다. 시험 결과 적합·출하 승인·절차 적합을 뜻하지 않는다.

## 검증 범위

합성 PDF8사례: 정상, 자기 필드 누락, 단위 오류, 중복 값, 시험차수1, 절차 조건 false, 다른 배치,
복수 배치를 실제 추출기→MD→계산으로 연결했다. 마지막2개는 예상한 배치 사유로 거부돼야 성공이다.
첫 fixture의 한 글자 제목/숫자 단독 줄은 기존 추출기에서 보존되지 않아6사례가 거부됐다.
그 실패 보고서를 보존하고 제목과 차수 표기를 실제 SP에 가까운 형식으로 고쳐 다시 시험했다.
**그 양식의 자동 추출까지 고쳤다는 뜻은 아니다.** 연결을 못 할 때 거부하는 경계는 유지한다.

제공 D00에서는 실제 중간체 제조번호 `SKY-CA220705`에 물리13쪽의 `130 L`만 연결했다.
Component B의 `143 L`, 완제품 머리말 번호, 제조용 세포주 번호는 빌리지 않았다. 이는 사실 추출
연결의 진단이며 제공 허가에 새로운 수행 조건을 만들어 승인한 시험이 아니다.

스캔/OCR 자동 복원, 임의 다열 표, 단계당 복수 배치, 모든 시험차수 표기, 조건부 필수시험 존재 판정,
운영 Finding/카드 연결은 남아 있다. 조건 규칙의 의미 검토·복합 논리식·개정 관계도 별도다.

## 재현

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_scoped_condition_facts.py tests/test_scoped_condition_pdf.py
.\.venv\Scripts\python.exe scripts/prove_scoped_condition_facts.py --rules-md docs/examples/scoped_condition_rules/conditions.md
```

API0. 합성9PDF와 보고서는 `.local_validation/scoped_facts_proof`에 저장한다.
명시적인 `--rules-md`는 덮어쓰지 않는다. 옵션이 없으면 **합성 fixture 전용** MD를 함께 만든다.
이는 임의 사용자 허가서의 조건을 자동 검토·승인하는 기능이 아니다. 전체 회귀 결과는 `WORK_STATUS.md`를 따른다.
